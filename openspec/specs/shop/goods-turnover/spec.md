# shop/goods-turnover Specification

## Purpose

Отчёт по оборачиваемости товаров направления «Магазин»: показывает оборот, остаток и коэффициент
оборачиваемости по каждой категории и подкатегории справочника товаров, в разрезе складов, за месяц.

## Requirements

### Requirement: Период отчёта
Отчёт по оборачиваемости SHALL строиться за один календарный месяц; период идентифицируется этим
месяцем (год + месяц).

#### Scenario: Запрос отчёта за месяц
- **WHEN** пользователь запрашивает отчёт по оборачиваемости за указанный месяц
- **THEN** система возвращает отчёт, построенный по данным этого месяца (с начала по конец месяца)

### Requirement: Полнота дерева категорий
Отчёт SHALL включать отдельную позицию для каждой категории справочника товаров, включая категории
любого уровня вложенности, а не только корневые или только листовые категории.

#### Scenario: Вложенная категория присутствует в отчёте
- **WHEN** в справочнике товаров есть категория с вложенной подкатегорией
- **THEN** в отчёте присутствуют обе категории как отдельные позиции, каждая со своими оборотом,
  остатком и коэффициентом оборачиваемости

#### Scenario: Категория без движений всё равно присутствует
- **WHEN** по категории за отчётный месяц не было ни оборота, ни остатка
- **THEN** категория всё равно присутствует в отчёте, с оборотом и остатком, равными нулю

### Requirement: Показатели позиции отчёта
Каждая позиция отчёта (категория × склад) SHALL содержать четыре показателя: количество и сумму
оборота (проданного за месяц), а также количество и сумму остатка (на конец месяца, по
себестоимости).

#### Scenario: Формирование позиции по категории на складе
- **WHEN** формируется позиция отчёта по категории на складе
- **THEN** она содержит количество и сумму оборота, а также количество и сумму остатка

### Requirement: Разбивка по складам
Отчёт SHALL быть разбит по складам: показатели оборота и остатка рассчитываются отдельно для
каждого склада, без объединения нескольких складов в одну позицию.

#### Scenario: Категория присутствует на нескольких складах
- **WHEN** категория товаров присутствует на нескольких складах
- **THEN** в отчёте есть отдельная позиция для каждой пары «категория-склад», с показателями,
  относящимися только к этому складу

### Requirement: Источник данных оборота
Оборот SHALL считаться только по проведённым документам «Отгрузка»: розничные продажи и отчёты
комиссионера в оборот не включаются. Возвраты в расчёт оборота не включаются и не уменьшают его.

#### Scenario: Розничная продажа не влияет на оборот
- **WHEN** за отчётный месяц по категории была розничная продажа товара, но не было отгрузок
- **THEN** оборот категории за этот месяц равен нулю

#### Scenario: Возврат не уменьшает оборот
- **WHEN** за отчётный месяц по товару категории оформлен возврат ранее отгруженного товара
- **THEN** сумма возврата не вычитается из оборота категории за этот месяц

### Requirement: Коэффициент оборачиваемости
Каждая позиция отчёта (категория × склад) SHALL содержать коэффициент оборачиваемости, вычисляемый
как оборот текущего месяца, делённый на среднее между остатком предыдущего месяца и остатком
текущего месяца: `Оборот(тек.) / ((Остаток(пред.) + Остаток(тек.)) / 2)`.

#### Scenario: Расчёт коэффициента при наличии данных за предыдущий месяц
- **WHEN** для категории и склада есть сохранённые данные отчёта за предыдущий месяц
- **THEN** коэффициент оборачиваемости текущего месяца рассчитывается по формуле
  `Оборот(тек.) / ((Остаток(пред.) + Остаток(тек.)) / 2)`

#### Scenario: Отсутствие данных за предыдущий месяц
- **WHEN** для категории и склада нет сохранённых данных отчёта за предыдущий месяц (например, это
  первый месяц, за который формируется отчёт, или категория появилась только в этом месяце)
- **THEN** коэффициент оборачиваемости этой позиции отсутствует (не рассчитывается и не
  отображается как ноль)

### Requirement: Просмотр прошлых периодов
Пользователь SHALL иметь возможность запросить и просмотреть отчёт по оборачиваемости за любой
прошлый месяц, за который отчёт уже формировался.

#### Scenario: Запрос отчёта за прошлый месяц
- **WHEN** пользователь выбирает месяц, отличный от текущего открытого
- **THEN** система возвращает сохранённый отчёт за выбранный месяц

### Requirement: Пересчёт открытого периода
Отчёт текущего (открытого, ещё не закрытого) месяца SHALL автоматически пересчитываться не реже
одного раза в час, отражая актуальные данные об обороте и остатке.

#### Scenario: Часовой пересчёт открытого месяца
- **WHEN** проходит очередной час для текущего открытого месяца
- **THEN** отчёт этого месяца пересчитывается заново по актуальным данным источника

### Requirement: Закрытие периода
У отчёта по оборачиваемости нет самостоятельного действия «закрыть месяц»: месяц отчёта по
оборачиваемости SHALL закрываться автоматически вместе с закрытием расчётного (зарплатного) периода
направления «Магазин» за тот же месяц. Закрытие SHALL сохранить текущее состояние отчёта этого
месяца как неизменяемый снэпшот и SHALL прекратить его дальнейший автоматический пересчёт.

#### Scenario: Закрытие зарплатного периода фиксирует отчёт
- **WHEN** закрывается расчётный (зарплатный) период направления «Магазин» за месяц
- **THEN** отчёт по оборачиваемости за этот же месяц фиксируется как неизменяемый снэпшот и
  перестаёт автоматически пересчитываться

#### Scenario: Пересчёт не выполняется после закрытия
- **WHEN** наступает очередной час пересчёта, но расчётный период этого месяца уже закрыт
- **THEN** отчёт этого месяца не пересчитывается, возвращаемые данные не меняются

#### Scenario: Просмотр отчёта закрытого месяца
- **WHEN** пользователь запрашивает отчёт закрытого месяца
- **THEN** система возвращает зафиксированные при закрытии данные, а не результат нового расчёта
