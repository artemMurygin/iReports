## Purpose

Описывает наблюдаемое поведение импорта закупочных цен товара из XLSX прайс-листа поставщика:
разбор файла, сопоставление позиций с каталогом МойСклад, что происходит с результатом сопоставления.
Модуль не покрывает остальную часть маркетинговой области (источники обращений, кампании и их
эффективность) — они не реализованы, это не пробел этого спека, а фактическое состояние
функциональности (см. `domains/shop/CLAUDE.md`).

## ADDED Requirements

### Requirement: Импорт цен — джоба с явными статусами, без повторного запуска
Импорт цен SHALL выполняться как отдельная джоба с одним из четырёх статусов: создана, выполняется,
завершена успешно, завершена с ошибкой. Джоба SHALL переходить из «создана» в «выполняется» ровно один
раз за свою жизнь; повторный запуск джобы, уже выполняющейся или уже завершившейся (успешно или с
ошибкой), SHALL отклоняться.

#### Scenario: Повторный запуск уже выполняющейся джобы отклоняется
- **WHEN** запрашивается запуск джобы импорта, которая уже находится в статусе «выполняется»
- **THEN** запуск отклоняется, статус джобы не изменяется

#### Scenario: Повторный запуск завершённой джобы отклоняется
- **WHEN** запрашивается повторный запуск джобы, уже завершённой успешно или с ошибкой
- **THEN** запуск отклоняется; новая попытка импорта возможна только как новая джоба

### Requirement: Обновление прогресса допустимо только у выполняющейся джобы
Снимок прогресса выполнения SHALL приниматься только для джобы в статусе «выполняется»; для
ещё не запущенной или уже завершённой джобы обновление прогресса SHALL отклоняться.

#### Scenario: Прогресс не запущенной джобы отклоняется
- **WHEN** для джобы в статусе «создана» (ещё не запущена) поступает обновление прогресса
- **THEN** обновление отклоняется

### Requirement: Строки прайс-листа категоризируются по названию товара; первое совпадение побеждает
Каждая строка прайс-листа SHALL быть отнесена ровно к одной товарной категории на основании названия
товара, проверяемого по фиксированному, упорядоченному набору правил; первое правило в порядке
проверки, которому название соответствует, SHALL определять категорию строки. Строка, не подошедшая
ни под одно правило, SHALL исключаться из дальнейшего импорта без ошибки.

#### Scenario: Строка вне всех категорий не участвует в импорте
- **WHEN** название товара в строке прайс-листа не соответствует ни одному из правил категоризации
- **THEN** строка не попадает ни в одну категорию и не участвует в дальнейшем импорте; импорт
  остальных строк не прерывается

### Requirement: Изменение цены принимается только для сопоставленных позиций с известной ценой
Итоговый список изменений закупочной цены SHALL включать только те строки прайс-листа, для которых
найдено соответствие в каталоге МойСклад и для которых источник задаёт цену; несопоставленные строки
или строки без цены SHALL исключаться из списка изменений без прерывания обработки остальных строк.

#### Scenario: Часть строк не сопоставлена — импорт всё равно завершается успешно
- **WHEN** часть строк прайс-листа не удалось сопоставить с товаром каталога МойСклад
- **THEN** несопоставленные строки исключаются из списка изменений цены, а импорт по остальным,
  сопоставленным строкам завершается успешно

### Requirement: Сбой любого шага пайплайна переводит джобу в статус ошибки, не прерывая приложение
Ошибка на любом шаге импорта (разбор файла, загрузка каталога, сопоставление, запись результата)
SHALL переводить джобу в статус «завершена с ошибкой» с сохранённым текстом ошибки, не прерывая работу
приложения.

#### Scenario: Ошибка одного из шагов фиксируется в статусе джобы
- **WHEN** один из шагов пайплайна импорта завершается исключением
- **THEN** джоба переходит в статус «завершена с ошибкой», текст ошибки сохраняется в джобе, ошибка
  не распространяется дальше обработки этой джобы

### Requirement: Успешный импорт записывает изменения и в МойСклад, и в результирующую таблицу
Выполнение импорта SHALL записывать вычисленные изменения закупочной цены как в саму ERP-систему
МойСклад (закупочная цена сопоставленных товаров), так и в результирующую таблицу (Google Sheets) —
оба шага выполняются в рамках одного успешного прохода импорта.

#### Scenario: После завершения импорта цены обновлены и в МойСклад, и в таблице результатов
- **WHEN** импорт цен завершился успешно, часть строк сопоставлена и получила изменение цены
- **THEN** закупочная цена соответствующих товаров в МойСклад обновлена согласно вычисленным
  изменениям, и те же изменения записаны в результирующую таблицу
