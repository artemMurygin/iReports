## Why

Правило зарплаты «за выполнение задачи» (`TaskCompletion`/`TaskCompletionShop`) сегодня целиком
скрыто в отчёте по зарплате, пока связанная задача не переведена в статус «Закрыта успешно» — ни
факт, ни прогноз не видны, даже когда задача уже создана и находится в работе. Заказчик (владелец
продукта iReports) явно попросил изменить это: сотрудник и руководитель должны видеть ожидаемую
сумму сразу после постановки задачи, а не только после её закрытия.

> Ревизия: первая версия этого change (см. историю) выводила прогноз только с момента «Выполнена», а
> факт — только с «Закрыта успешно». По итоговой обратной связи заказчика прогноз должен быть виден
> сразу при постановке задачи, а факт должен капать раньше — на отметке исполнителя «Выполнена», без
> ожидания подтверждения руководителем. Ниже — уже финальная версия правила.

## What Changes

- Строка правила `TaskCompletion` появляется в отчёте по зарплате сразу, как только задача заведена
  на текущий период — раньше строка отсутствовала целиком, пока задача не была закрыта успешно.
- Прогноз (`amount.prognose`) равен сумме начисления по умолчанию (`config.defaultAmount`) СРАЗУ, с
  момента постановки задачи — независимо от её статуса.
- Факт (`amount.fact`) равен 0, пока исполнитель не переведёт задачу в статус «Выполнена» (`DONE`) —
  с этого момента факт становится равен той же сумме.
- Дальнейшие переходы статуса (`CLOSED_SUCCESSFULLY`, `CLOSED_UNSUCCESSFULLY`, `REWORK` — все
  достижимы только через «Выполнена») НЕ откатывают факт автоматически: раз сумма «капнула», она
  остаётся, пока руководитель не скорректирует её сам.
- Руководитель по-прежнему может вручную исправить сумму при закрытии периода
  (`SetTaskCompletionLineReward`, уже существующий механизм, не меняется) — например, уменьшить её и
  указать обязательный комментарий, если по факту сделано меньше, чем предполагалось.
- Поведение зеркально меняется для обоих направлений — `service` (`TaskCompletion`) и `shop`
  (`TaskCompletionShop`).

## Functional Requirements

- **FR1**: Пока задача существует на текущий период (в любом статусе), `amount.prognose` строки
  правила `TaskCompletion`/`TaskCompletionShop` равен `config.defaultAmount`.
- **FR2**: `amount.fact` строки равен 0, пока задача не в статусе «Выполнена» (`DONE`) или позже.
- **FR3**: С момента, когда задача достигла статуса «Выполнена» (`DONE`), `amount.fact` равен
  `config.defaultAmount` — и остаётся таким при любых последующих переходах статуса
  (`CLOSED_SUCCESSFULLY`/`CLOSED_UNSUCCESSFULLY`/`REWORK`), без автоматического отката.
- **FR4**: Руководитель сохраняет возможность вручную скорректировать сумму начисления при закрытии
  периода с обязательным комментарием (существующий механизм `SetTaskCompletionLineReward`,
  `requiresManualInput` — без изменений).

## Capabilities

### Modified Capabilities
- `service/accounting`: правило «за выполнение задачи» — новая видимость строки по статусу задачи
  (было: невидима до `CLOSED_SUCCESSFULLY`; стало: прогноз виден с момента постановки задачи, факт —
  с момента «Выполнена», без автоотката на последующих статусах).
- `shop/accounting`: то же самое, зеркально.

## Impact

- **Backend**: `TaskCompletion.calculate()`
  (`domains/service/modules/accounting/domain/entities/salary-rules/task-completion.entity.ts`) и
  `TaskCompletionShop.calculate()`
  (`domains/shop/modules/accounting/domain/entities/salary-rules/task-completion.entity.ts`) — PROGNOSE
  теперь не зависит от статуса задачи (всегда `defaultAmount`, пока задача заведена), FACT зависит от
  нового предиката `SalaryTask.isFactAccrued()`/`ShopSalaryTask.isFactAccrued()` («не NEW и не
  IN_PROGRESS»). Ни персистентность, ни HTTP-контракты, ни `SetTaskCompletionLineReward`/документ
  начисления закрытого периода не затрагиваются — изменение целиком в доменном слое расчёта открытого
  периода.
- **Contracts/Frontend**: не затрагиваются — форма `CalculationLine`/ответа отчёта не меняется,
  меняются только значения `amount.fact`/`amount.prognose` для существующего типа строки.
