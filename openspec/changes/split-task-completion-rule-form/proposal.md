## Why

Форма создания зарплатного правила «за выполнение задачи» сейчас одна и та же для разового и
регулярного правила, с условно показываемым блоком шаблона. Для регулярного правила это заставляет
руководителя описывать задачу дважды: один раз через панель создания задачи (название, дедлайн,
ссылки), второй раз — теми же полями, но как шаблон автосоздания. Для разового правила, наоборот, поля
выбора отчётного периода задачи и суммы начисления не выделены как самостоятельный шаг и теряются
рядом с переключателем «разовое / регулярное».

## What Changes

- Разделить форму создания правила «за выполнение задачи» на два самостоятельных сценария, которые
  выбираются в начале (вместо одной формы с условно скрываемым блоком шаблона):
  - **Разовая задача** — создание и привязка задачи остаются как сейчас (через панель создания задачи:
    название, дедлайн, ссылки), плюс явный выбор отчётного периода, к которому привязывается эта
    задача, и суммы начисления за неё.
  - **Регулярная задача** — только шаблон, как сейчас (название, дедлайн текущим числом месяца или со
    смещением после отчётного периода, описание, ссылки) — без отдельного шага ручного создания первой
    задачи через панель задач: первая задача регулярного правила автосоздаётся из шаблона так же, как
    задачи всех последующих периодов.
- **BREAKING**: контракт создания правила `TaskCompletion`
  (`taskCompletionSalaryConfigRequestSchema`) — `taskId` обязателен только при `isRecurring: false`;
  при `isRecurring: true` `taskId` в payload больше не передаётся.
- Бэкенд (`service` и `shop` домены) — создание первой задачи регулярного правила переиспользует
  существующий механизм автосоздания задачи по шаблону вместо ожидания уже готового `taskId` от
  фронтенда.

## Capabilities

### New Capabilities

_Нет — изменение затрагивает только поведение существующей возможности._

### Modified Capabilities

- `service/accounting`: требование «Разовое и регулярное правило «за выполнение задачи»» — уточняется
  порядок указания отчётного периода и задачи для каждого из двух раздельных сценариев создания
  (разовая задача с явным выбором периода и суммы начисления vs регулярная задача без ручного создания
  первой задачи).
- `shop/accounting`: то же требование, зеркально для домена `shop`.
