## Новые компоненты UI Kit
Пусто — все элементы собраны из существующих компонентов `uDEum` (`ERP/Atom/*`, `ERP/Molecule/*`,
`ERP/Organism/*`). Композиции «карточка роли» (имя + счётчик сотрудников + иконки
переименования/удаления или бейдж «Системная») и «строка матрицы прав» (лейбл права + код +
чекбоксы по ролям) — это одноразовые страницы-специфичные композиции из существующих атомов
(`ERP/Atom/Icon Button`, `ERP/Atom/Badge`, `ERP/Atom/Checkbox`, `text`), а не новые переиспользуемые
компоненты — сохранять их в `uDEum` не требуется, так как больше нигде в проекте не переиспользуются.

## Отклонения от architecture.md
- Отсутствие мобильного брейкпоинта для `RolesManagement` — десктоп-only админ-страница, согласовано с пользователем.
- **Добавлена страница `pages/Login`** (`/login`, standalone/iOS), которой не было в исходной версии architecture.md. Изначально `app/` предполагал автоматический OAuth-редирект без участия пользователя при отсутствии валидной сессии в standalone/iOS-контексте. Пользователь запросил экран-шлюз с явным призывом «Войти через Bitrix24» — так UX предсказуемее (нет немого auto-redirect на каждый визит без сессии, в т.ч. при истёкшей сессии) и добавляет фирменный момент входа. architecture.md обновлён: добавлены `pages/Login`, `pages/Login/ui/LoginGate`, хук `useBitrixLogin` в `features/Auth`, скорректирован раздел про `app/`-bootstrap.
- Исправлена ошибка в первой версии дизайна: компонент `ERP/Molecule/Tabs` по умолчанию содержит 3 таба, а не 2 — на экранах `RolesManagement` (обе вкладки) третий, неиспользуемый таб (дубль подписи «Сотрудники») не был отключён и отображался лишним. Отключён (`enabled: false`) на обоих артбордах (`s5nMLx`, `F6d3a`).
- **Уточнён источник данных матрицы «роль × permission»** на экране «Роли и права» (`s5nMLx`): роли (колонки) и группы прав/названия/коды прав (строки) на макете — иллюстративные placeholder-данные для демонстрации layout, а не финальный контент. По итогам обсуждения с пользователем зафиксировано в `design.md` (Decision 12) и `specs/roles/spec.md`: сами КОДЫ прав (строки матрицы) наполняются из типизированного реестра в коде backend через сид при деплое (`PermissionsCatalogSeeder`, см. `architecture.md`) — администратор через UI выбирает и назначает ролям права ИЗ этого каталога, но не может создать новый код права, отсутствующий в коде.
