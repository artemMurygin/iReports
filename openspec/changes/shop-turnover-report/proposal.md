## Why

У направления «Магазин» нет отчёта по оборачиваемости товаров: невозможно за один взгляд увидеть
оборот (сумму проданного) и остаток (в рублях и штуках) по категориям и подкатегориям справочника
товаров МойСклад, а также коэффициент оборачиваемости по каждой категории и складу. Данные для
оборота уже есть в БД (`MoySkladDemand`/`MoySkladDemandPosition`, синкаются каждые 5 минут ради
расчёта зарплаты), но не агрегируются по дереву категорий и складам и нигде не показываются
пользователю. Остатков (складских, в рублях по себестоимости и в штуках) в проекте нет вообще.

## What Changes

- Новая синхронизация справочника складов МойСклад (`MoySkladStore`, `GET /entity/store`) — в
  проекте пока нет ни модели, ни синка складов.
- В существующий синк `MoySkladDemand` (`moysklad-sync.service.ts`) добавляется сохранение склада
  отгрузки (`store`) — поле уже приходит от МойСклад, но сейчас отбрасывается при апсерте.
- Новый отчёт по оборачиваемости магазина за месяц: оборот (сумма проданного, ₽ и шт.) и остаток
  (себестоимость остатка на конец месяца, ₽ и шт.) по каждой категории и каждой вложенной
  подкатегории справочника товаров, отдельно по каждому складу.
- Оборот считается только по документам «Отгрузка» (`Demand`) — без розничных продаж
  (`RetailDemand`) и без отчётов комиссионера; вычисляется из уже засинканных
  `MoySkladDemandPosition` (готовое поле `sum`), без новых обращений к МойСклад.
- Остаток получается фоновой почасовой синхронизацией: новая крон-задача раз в час запрашивает
  асинхронный Расширенный отчёт об остатках МойСклад (`GET /report/stock/bystore?async=true&
  groupBy=product`, без `limit`/`offset`) и добавляет новый снимок остатков по товару и складу в
  новую таблицу `MoySkladStock` — история снимков (не перезаписывается), отдельно от самого
  построения отчёта по оборачиваемости.
- Коэффициент оборачиваемости по каждой паре «категория × склад»:
  `Оборот текущего месяца / ((Остаток прошлого месяца + Остаток текущего месяца) / 2)`.
- Просмотр отчёта за прошлые периоды (месяцы) — не только за текущий; при раскатке — за последний
  год, включая разовый бэкфилл `storeId` на исторических `Demand` и остатков на конец каждого
  прошлого месяца (через легаси-эндпоинт МойСклад с историческим срезом), встроенный в существующий
  механизм `initialUpload` (`npm run initial`/`npm run initialProd`), без отдельного скрипта.
- Фоновый пересчёт отчёта текущего (открытого) месяца каждый час — новая крон-задача.
- Закрытие месяца останавливает пересчёт этого месяца и фиксирует его данные как снэпшот; у этого
  отчёта нет самостоятельного действия «закрыть» — закрытие происходит автоматически вместе с
  закрытием расчётного (зарплатного) периода направления «Магазин» за тот же месяц (переиспользуется
  существующая таблица `AccountingPeriod`/агрегат `ShopAccountingPeriod` и событие
  `ShopAccountingPeriodClosedDomainEvent`, без своей отдельной таблицы периода).

## Capabilities

### New Capabilities
- `shop/goods-turnover`: отчёт по оборачиваемости товаров направления «Магазин» — оборот и остаток
  по дереву категорий и складам за месяц, коэффициент оборачиваемости по категории и складу,
  ежечасный пересчёт открытого месяца, закрытие месяца с фиксацией снэпшота, просмотр отчётов за
  прошлые периоды.

## Impact

- **Backend**: расширение существующего `backend/src/domains/shop/modules/warehouse/` — новая
  Prisma-модель `MoySkladStore` и синк складов, дополнение синка `MoySkladDemand` полем `storeId`
  (название склада — через join на `MoySkladStore`, не дублируется), новая Prisma-модель
  `MoySkladStock` (история почасовых снимков остатков по товару и складу) и почасовая крон-задача
  синка через асинхронный отчёт об остатках МойСклад, доменная логика построения/хранения отчёта
  (рулап по дереву `MoySkladProductFolder`, уже есть `ProductFolderTreeService`, читает уже
  засинканные `MoySkladDemand`/`MoySkladStock`), отдельная почасовая крон-задача пересчёта отчёта,
  обработчик `ShopAccountingPeriodClosedDomainEvent` для фиксации снэпшота, новая Prisma-модель строк
  отчёта `MoySkladTurnoverReportLine`, HTTP-эндпоинт для чтения отчёта за период. Требуется добавить
  `SHOP_ACCOUNTING_PERIOD_REPOSITORY` в `exports` `ShopAccountingModule` (сейчас не экспортируется).
  Доработка `backend/src/scripts/initialUploadData.ts`/`UploadInitialMoySkladDataHandler`: синк
  складов и разовый бэкфилл `storeId` + месячных снимков остатков за прошлый год для раскатки на
  продакшен.
- **Contracts** (`contracts/`): схемы запроса/ответа отчёта по оборачиваемости магазина.
- **Frontend**: новая страница/раздел отчёта по оборачиваемости с деревом категорий, разбивкой по
  складам, выбором месяца/периода.
- **ENDPOINTS.md**: добавить новые backend-эндпоинты после реализации.
- **Внешняя зависимость**: точный механизм опроса статуса и получения результата асинхронного
  отчёта об остатках МойСклад (`async=true`) подтверждён частично — параметр запуска и запрет
  `limit`/`offset` подтверждены документацией, точный формат опроса задачи требует проверки на
  этапе реализации.
