## Context

Мотивация и объём — в `proposal.md`, требования — в `specs/shop/price-import-schedule/spec.md`.

Текущее состояние (`backend/src/domains/shop/modules/marketing/pricing`):
- `StartPriceImportHandler.execute()` принимает `StartPriceImportCommand({ fileBase64 })`, **await-ит весь пайплайн** и всегда возвращает `{ id }`: ошибки перехватываются внутри и переводят `PriceImportJob` в `FAILED` (см. `catch` в хендлере). Поэтому по возвращаемому значению успех от ошибки не отличить — результат читается из `PRICE_IMPORT_JOB_STORE.findById(id)` (`status`, `errorMessage`).
- Хранилище джоб — in-memory (`InMemoryPriceImportJobStore`); `findActive()` отдаёт выполняющуюся (CREATED/RUNNING) джобу.
- HTTP-контроллер запускает команду fire-and-forget (`void commandBus.execute`); cron сможет дождаться её через `await`.
- Cron-инфраструктура: `@ProdCron(expr)` (`src/shared/cron/prod-cron.decorator.ts`, работает при `ENABLE_CRON=true`), `@nestjs/schedule`. Redis подключён (`RedisModule`).
- Google: `google-sheets.instance.ts` создаёт `GoogleAuth` из `GOOGLE_SERVICE_ACCOUNT_EMAIL`/`GOOGLE_PRIVATE_KEY` со scope `spreadsheets`; пакет `googleapis` уже установлен.
- Telegram-интеграции в проекте нет.

## Goals / Non-Goals

**Goals:**
- Планировщик в модуле `pricing`, не дублирующий пайплайн: он только получает файл, запускает `StartPriceImportCommand`, читает итог и шлёт уведомление.
- Порты для внешнего мира (источник прайса, хранилище версии, нотификатор), чтобы оркестрацию можно было тестировать без Drive/Redis/Telegram.

**Non-Goals:**
- Изменение пайплайна импорта, HTTP-эндпоинтов, фронтенда и `sheets-app`.
- Перевод job-store на персистентное хранилище.
- Повторные попытки (retry) при ошибке в тот же день; ручной запуск расписания; хранение истории запусков.
- Подробные отчёты в Telegram (по требованию — только факты).

## Decisions

1. **Оркестрация — отдельный application-сервис, а не хендлер.** `RunScheduledPriceImportService` (`application/services`) делает: получить метаданные файла → сравнить версию → скачать → `commandBus.execute(new StartPriceImportCommand(...))` → прочитать джобу из стора по `command.id` → уведомить → при успехе сохранить версию. Cron-класс (`interface/cron/scheduled-price-import.cron.ts`, `@ProdCron('0 12 * * 1-5')`) только вызывает сервис. *Альтернатива:* логика внутри cron-класса — отклонена: не тестируется без декоратора и таймеров.

2. **Расписание и часовой пояс.** Выражение `0 12 * * 1-5` с `timeZone: 'Europe/Moscow'` (бизнес в РФ; серверный TZ в Docker, как правило, UTC). Существующий `ProdCron` не принимает опции, поэтому расширяем его необязательным вторым аргументом `options` (`CronOptions`), не меняя поведение текущих вызовов.

3. **Определение «прайс не изменился» — по названию файла.** Файл в папке один и редактируется на месте; при каждом обновлении его название меняется (требование заказчика), поэтому достаточно сравнить `name` из метаданных Drive с последним успешно выгруженным. Не нужно ни хешей, ни скачивания «на пробу». *Альтернативы:* `md5Checksum` — у нативных Google-таблиц его нет; `modifiedTime` — меняется при любой правке и не отражает «поставщик обновил прайс».

4. **Хранилище версии — Redis, ключ `price-import:schedule:last-file-name`, без TTL.** Redis уже подключён, схему БД и миграции менять не нужно, значение — одна строка. Порт `PriceListVersionStore` (`get()/save(name)`), реализация поверх Redis. Название сохраняется только после успешной выгрузки (спека: «Выгрузка только при изменении прайса»). *Альтернатива:* таблица Prisma — тяжелее ради одного значения; in-memory — теряется при каждом деплое и вызывает повторную выгрузку.

5. **Источник прайса — порт `PriceListSource`.** Методы: `findPriceListFile(): Promise<{ id, name, mimeType }>` (кидает доменные ошибки «нет файла»/«несколько файлов» при `!= 1` результатов) и `download(file): Promise<Buffer>`. Реализация `GoogleDrivePriceListSource` (`infrastructure/drive`) использует `googleapis` Drive v3: `files.list` с `q: "'<folderId>' in parents and trashed=false"`, поля `id, name, mimeType`. Скачивание зависит от типа: для Google-таблицы (`application/vnd.google-apps.spreadsheet`) — `files.export` с MIME `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`; для загруженного `.xlsx` — `files.get({ alt: 'media' })`. Так сервис работает в обоих случаях, а парсер получает привычный XLSX. Аутентификация — тот же сервисный аккаунт; чтобы не расширять scope у Sheets-клиента, создаётся отдельный `GoogleAuth` со scope `drive.readonly`, но с теми же `GOOGLE_SERVICE_ACCOUNT_EMAIL`/`GOOGLE_PRIVATE_KEY`. Общий код чтения кредов выносим в небольшую функцию в `integrations/google-sheets`, чтобы не копировать разворачивание `\n` в ключе. *Альтернатива:* добавить Drive-scope в существующий клиент Sheets — отклонена: расширяет права Sheets-клиента без необходимости.

6. **Уведомления — порт `PriceImportNotifier` с тремя методами** (`notifyUploaded`, `notifyUnchanged`, `notifyFailed`) и реализация `TelegramPriceImportNotifier`, поверх общей интеграции `src/integrations/telegram` (`TelegramService.sendMessage(chatId, text)` — HTTPS `POST https://api.telegram.org/bot<token>/sendMessage`, без SDK, через уже используемый в проекте HTTP-клиент). Тексты сообщений — константы в infrastructure. Токен — `TELEGRAM_BOT_TOKEN` из env; `chatId` — в `pricing.config.ts` рядом с остальной конфигурацией модуля вместе с `PRICE_LIST_DRIVE_FOLDER_ID`. Любой сбой отправки перехватывается внутри нотификатора и логируется (спека: «Отказоустойчивость уведомлений») — он не влияет на сохранение версии.

7. **Текст ошибки в Telegram — обобщённый.** Нотификатор принимает только категорию/короткое описание причины («файл не найден в папке», «выгрузка завершилась ошибкой»); `job.errorMessage` и тексты исключений пишутся только в лог, чтобы не утекали внутренние детали (спека: «Уведомление об ошибке»).

8. **Защита от параллельных запусков.** Перед стартом сервис проверяет `jobStore.findActive()`; если джоба выполняется — ошибка «выгрузка уже выполняется» → уведомление, версия не сохраняется. Для нескольких инстансов бэкенда распределённая блокировка не вводится: проект запускается одним контейнером `backend` (`docker-compose.yml`).

9. **Отмена и ошибки.** Статусы `FAILED` и `CANCELLED` итоговой джобы трактуются как ошибка (уведомление, версия не сохраняется); `COMPLETED` — успех. Любое исключение сервиса (Drive, download, неожиданное) перехватывается верхнеуровневым `try/catch`, логируется и превращается в `notifyFailed` — cron никогда не бросает необработанное исключение.

10. **Трассируемость.** Требования спеки — `FR`-идентификаторов в `proposal.md` нет (используются Requirements в спеке), поэтому JSDoc портов и сервиса ссылаются на `spec: shop/price-import-schedule#<requirement>` по конвенции `openspec/specs/conventions/documentation`.

## Risks / Trade-offs

- [Поставщик отредактировал прайс, но не поменял название] → система посчитает прайс неизменным и пришлёт «не изменился»; сотрудники в этом случае загружают вручную (на это и рассчитан текст уведомления). Принятое допущение: название меняется при каждом обновлении.
- [Название изменили, содержимое осталось прежним] → будет лишняя, но безвредная повторная выгрузка.
- [Сервисный аккаунт не расшарен на папку или не включён Drive API в проекте Google Cloud] → первый запуск завершится уведомлением об ошибке; закладываем проверку в чек-лист деплоя (tasks).
- [Экспорт Google-таблицы ограничен по размеру (лимит `files.export` ~10 МБ)] → для текущего прайса достаточно; при превышении Drive вернёт ошибку, придёт уведомление об ошибке.
- [Ключ Redis потерян/очищен] → следующий запуск выгрузит файл повторно; повторная выгрузка идемпотентна (цены перезаписываются теми же значениями), вред — только лишнее уведомление и нагрузка на AI.
- [Время выгрузки ~несколько минут, ответ AI может занимать 170+ секунд на категорию — см. логи] → cron-запуск `await`-ит весь пайплайн; повторный запуск в тот же день не планируется, пересечения с ручной выгрузкой закрыты решением 8.
- [Telegram недоступен] → логируем и продолжаем; сотрудники не получат уведомление, но цены обновятся.

## Migration Plan

1. Включить Drive API в проекте Google Cloud сервисного аккаунта; расшарить папку на его email (read-only).
2. Создать бота, добавить в группу, получить `chat_id`; прописать `TELEGRAM_BOT_TOKEN` в env продакшена, `chat_id` и id папки — в `pricing.config.ts`.
3. Задеплоить; в первый будний день после 12:00 проверить уведомление (при пустом Redis ожидается выгрузка).
4. Откат: убрать cron (или `ENABLE_CRON=false`) — ручная выгрузка не затронута, миграций БД нет.
