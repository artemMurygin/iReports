## MODIFIED Requirements

### Requirement: Защита страниц/роутов на frontend
Пользователь без нужного permission SHALL не видеть соответствующий пункт меню и SHALL получать
явный экран "нет доступа" при прямом переходе по URL защищённой страницы; при этом backend SHALL
самостоятельно возвращать 403 при прямом обращении к соответствующему API, независимо от проверки
на frontend. Это требование SHALL применяться ко всем страницам frontend, чьи данные защищены на
backend хотя бы одним `@RequirePermissions`, а не только к отдельным страницам. Роут SHALL иметь
возможность требовать не один, а несколько permission-кодов через OR-семантику — пользователю
достаточно обладать хотя бы одним из перечисленных, чтобы увидеть пункт меню и открыть страницу.

#### Scenario: Прямой переход по URL без прав показывает экран "нет доступа"
- **WHEN** пользователь без нужного permission переходит по прямой ссылке на защищённую страницу
- **THEN** frontend показывает экран "нет доступа", а не содержимое страницы

#### Scenario: Backend не полагается на проверку frontend
- **WHEN** пользователь без permission напрямую обращается к API защищённой страницы, минуя
  frontend
- **THEN** backend возвращает 403 независимо от того, что делает frontend

#### Scenario: Все permission-защищённые страницы скрыты в меню без доступа
- **WHEN** у пользователя нет ни одного из permissions, защищающих раздел (например, зарплатные
  отчёты, задачи, учёт), а backend соответствующих API помечен `@RequirePermissions`
- **THEN** пункт меню этого раздела не отображается в Sidebar/Subnav/Drawer, независимо от того,
  является ли раздел уже покрытым route-guard'ом сегодня или добавляется этим изменением

#### Scenario: Доступ по любому из нескольких permissions открывает страницу
- **WHEN** роут защищён несколькими permission-кодами (например, отчёт по зарплате «Все» на
  `/salaries` одновременно запрашивает `service-accounting:view_all_salary_report` и
  `shop-accounting:view_all_salary_report` — по одному на каждое направление), а у пользователя
  есть хотя бы один из них
- **THEN** frontend показывает пункт меню и содержимое страницы (в объёме направления, к которому
  есть доступ), не требуя одновременного наличия всех перечисленных permissions

#### Scenario: Отсутствие любого из требуемых permissions скрывает страницу
- **WHEN** роут защищён несколькими permission-кодами через OR-семантику, а у пользователя нет ни
  одного из них
- **THEN** пункт меню не отображается, а при прямом переходе по URL frontend показывает экран "нет
  доступа"
