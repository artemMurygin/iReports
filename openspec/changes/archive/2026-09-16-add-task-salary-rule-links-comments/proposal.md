## Why

Карточка задачи сейчас показывает только собственные поля задачи (название, описание, дедлайн,
статус, ответственный) — но не показывает, что эта задача даёт основание для начисления по
зарплатному правилу, и не показывает само начисление. Руководителю и ответственному сотруднику
приходится отдельно искать связанное правило и начисление вне карточки задачи. Кроме того, у задачи
нет места для внешних ссылок (например, на файл с результатом работы) и нет истории обсуждения —
любые пояснения и договорённости по задаче сейчас никак не фиксируются рядом с ней.

## What Changes

- На карточке задачи (боковая панель) появляется блок с связанным зарплатным правилом (если задача
  на него ссылается) и с начислением, которое отображается по этой задаче (если оно уже есть в
  отчёте сотрудника).
- Клик по связанному зарплатному правилу открывает такую же боковую панель, как у задачи, но с
  описанием этого правила (тип, направление, параметры) — без перехода на отдельную страницу
  редактирования.
- Добавляется поле для одной или нескольких ссылок на задаче — с возможностью добавить, посмотреть и
  удалить ссылку прямо в карточке задачи.
- Добавляются комментарии к задаче: автор, дата/время, текст сообщения — видны все в карточке задачи,
  можно добавить новый.
- Зарплатное правило и начисление, ссылающиеся на задачу, становятся доступны для поиска по
  идентификатору задачи (обратный запрос) — без изменения текущего инварианта: сама задача по-прежнему
  не хранит и не знает о правиле (см. `tasks#Requirement: Задача — полностью самостоятельная сущность,
  не знающая о зарплатных правилах`), обратный поиск обслуживается на стороне правила/начисления.
- Зарплатное правило становится доступно для получения по собственному идентификатору (без загрузки
  всей мотивационной схемы целиком) — это нужно, чтобы боковая панель могла запросить только одно
  правило.

## Capabilities

### New Capabilities
- `tasks/salary-rule-panel`: карточка задачи показывает связанное зарплатное правило и начисление за
  эту задачу; клик по правилу открывает боковую панель с описанием правила.
- `tasks/links`: одна или несколько ссылок, прикреплённых к задаче.
- `tasks/comments`: комментарии к задаче — автор, время, текст.

### Modified Capabilities
- `service/accounting`: зарплатное правило и связанное с ним начисление становятся доступны для
  поиска по идентификатору задачи, на которую они ссылаются; зарплатное правило становится доступно
  для получения по собственному идентификатору.
- `shop/accounting`: то же самое для направления shop (зеркальный домен).

## Impact

- **Backend**: `backend/src/modules/tasks/` — новые сущности `TaskComment` и `TaskLink` (Prisma-модели,
  репозитории, use-case'ы, HTTP-эндпоинты создания/чтения/удаления в рамках задачи).
  `backend/src/domains/service/modules/accounting` и `backend/src/domains/shop/modules/accounting` —
  новый метод порта/репозитория "найти правило и начисление, ссылающиеся на taskId" и новый
  HTTP-эндпоинт получения одного правила по id. `backend/src/modules/tasks/` строит собственную
  сущность для отображения сводки по правилу/начислению на карточке задачи, не вызывая напрямую
  application-сервисы модулей `accounting` (см. правило изоляции межмодульных зависимостей в
  `backend/CLAUDE.md`).
- **Contracts**: новые Zod-схемы для `TaskComment`, `TaskLink`, сводки по правилу/начислению на
  карточке задачи, детального представления зарплатного правила.
- **Frontend**: `features/TaskStatusControl` — новый блок с правилом/начислением и ссылками/
  комментариями на карточке задачи; новая фича для боковой панели зарплатного правила, переиспользующая
  `shared/ui-kit/organisms/SidePanel` (по образцу `features/TaskStatusControl`).
- Внешние системы (RemOnline, МойСклад, Bitrix24) не затрагиваются — все новые сущности полностью
  локальны для iReports.
