# UI Design: replace-bitrix-task-integration

## Источник дизайна
- **.pen файл**: `design/sallary-first-iteration.pen`
- **UI Kit**: фрейм `uDEum` в этом же файле — переиспользуемые компоненты (кнопки, инпуты, карточки, KPI, таблицы, чипы, бейджи и т.д.)

## Статус визуальной проверки

В процессе дизайна в этой сессии Pencil MCP временно перестал рендерить содержимое новых/изменённых
узлов (`TakeScreenshot`/`Export` возвращали пустое изображение, хотя структура документа была
корректна) — рендер восстановился позже в той же сессии. Все 9 экранов/состояний ниже пересняты
экспортом после восстановления и просмотрены — визуально подтверждены. При повторной проверке в
шапке шагов мастера создания правила (`FwNov`, `EdCuh`) был найден и исправлен реальный баг:
скопированные с существующего экрана редактирования правила заголовок/хлебные крошки/кнопка
«Сохранить правило» не соответствовали контексту создания — заменены на текст, соответствующий шагу
мастера, дублирующая кнопка сохранения в шапке скрыта (сохранение — только через кнопку в теле
формы).

## Новые компоненты UI Kit

Не потребовалось — везде, где нужен был статус-бейдж (6 значений жизненного цикла задачи), переиспользован
существующий `ERP/Atom/Badge` (`PGyPp`) с разными `fill`/цветом текста по палитре файла
(`$info-soft`/`$info-ink`, `$warn-soft`/`$warn-ink`, `$brand-soft`/`$ok-ink`, `$danger-soft`/`$danger`,
`$violet-soft`/`$violet-ink`, нейтральный `$canvas`+`$hairline`/`$ink-muted` для «Новая») — отдельного
переиспользуемого компонента не заводилось, т.к. `ERP/Atom/Badge` уже параметризуется через
`descendants`, ровно так же, как для остальных статусных бейджей в файле (см. пример `Badge Администратор`
и т.п.).

Единственное изменение в самом UI Kit — в общий топ-нав (`ERP/Organism/Topnav`, `dRfe8`) добавлен новый
пункт раздела **«Задачи»** (`t7zmq`, между «Зарплата» и «Настройки») — он появится на всех страницах
проекта, не только на новых.

## Отклонения от architecture.md

- **Мобильный Bottom Nav не получил отдельного 6-го таба «Задачи».** `ERP/Mobile/Bottom Nav` — не
  slot-компонент, а фиксированный набор из 5 пунктов (Продажи/Аналитика/Зарплата/График/Ещё) во всех
  уже существующих мобильных экранах проекта. Добавление 6-го пункта либо сломало бы этот компонент
  во всех остальных мобильных макетах файла, либо потребовало бы неочевидного решения о том, какой
  из существующих пунктов убрать. Вместо этого на мобильном экране `/tasks` подсвечен существующий
  пункт «Ещё» — обычный паттерн для раздела, которого нет в основной навигации. Нужно согласовать с
  пользователем, не появится ли у фронтенда сложность с тем, куда именно вести из «Ещё».
- **Не строил отдельный мобильный артборд для ролей «Руководитель»/терминальных статусов задачи** —
  только для базового варианта «Ответственный, В работе» (`cmZjM`). Разметка ролей руководителя
  идентична десктопным `QpFcx`/`yZE5X`, просто в виде bottom sheet вместо drawer; отдельно не
  дублировал, чтобы не плодить экраны сверх необходимого (руководительские сценарии в проекте и так
  тяготеют к десктопу — ни у одного экрана создания/проверки зарплатных правил нет мобильной версии).
- **Отдельный артборд для статуса «Закрыто неуспешно»/«На доработку» в карточке статуса не
  заводился** — набор полей идентичен `yZE5X` («Закрыта успешно»), меняется только цвет/текст бейджа
  по уже определённой палитре (danger/violet) — сочтено достаточным описать текстом в таблице выше.
- **`SalaryReportV2`/`RuleSourcesRail` не получил нового артборда** — изменение не влияет на
  разметку (см. таблицу «Экраны»).
