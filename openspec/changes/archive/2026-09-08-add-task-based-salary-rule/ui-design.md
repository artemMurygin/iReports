# UI Design: add-task-based-salary-rule

## Источник дизайна
- **.pen файл**: `design/sallary-first-iteration.pen`
- **UI Kit**: фрейм `uDEum` в этом же файле — переиспользуемые компоненты (кнопки, инпуты, карточки, KPI, таблицы, чипы, бейджи и т.д.)

**Скоуп этой итерации**: по явному запросу — только интерфейс **создания/редактирования правила `TaskCompletion`**, для `service` и `shop`, десктоп и мобильный. Остальные Pages из architecture.md (`SalaryAccrualDocument` — ручной ввод суммы/комментария, `SalaryReportV2` — отображение статуса/ссылки в детализации) в этой итерации не спроектированы — см. «Отклонения от architecture.md».

## Отклонения от architecture.md

- Спроектирована только часть `SalaryRuleDetail`, относящаяся к `TaskCompletion` (по прямому запросу пользователя — «нужно отрисовать интерфейс создания задачи в зарплатном правиле»). `SalaryAccrualDocument` (модалка `SetTaskRewardModal`, ручной ввод суммы+комментария) и `SalaryReportV2` (детализация с названием/ссылкой на задачу через `RuleSourcesRail.tsx`, бейдж `TaskStatusBadge`) из architecture.md — не спроектированы, нужен отдельный проход по ui-design, если требуется макет и для них.
- В architecture.md компонент `TaskCompletionRuleFields` был обозначен как потенциально новый UI-компонент (`SalaryRuleForm/ui/RuleFormCard/`, new). По факту дизайна отдельного нового *визуального* компонента не потребовалось — все поля собраны из существующих `uDEum`-примитивов; `TaskCompletionRuleFields` на кодовом уровне (React) по-прежнему имеет смысл как контейнер этой группы полей, но это не новый UI Kit компонент в Pencil.
- Поле «Название задачи (в Bitrix24)» в architecture.md явно не упоминалось (там были только `deadline`, `isRecurring`) — добавлено при проектировании, так как без него нечего было бы показать как заголовок создаваемой в Bitrix24 задачи. Также добавлено необязательное поле «Описание задачи» (текстовое, для описания в Bitrix24). Оба поля соответствуют `TaskCompletion.props`/данным, передаваемым в `BitrixTasksGatewayPort.createTask({ title, description, deadline, ... })` (см. architecture.md, Method Signatures) — расхождение чисто в уровне детализации UI, не в архитектуре.
