## Why

Правило зарплаты `TaskCompleted` сейчас опирается на временный внутренний воркфлоу подтверждения (`TaskCompletion`: произвольный текст + ручное подтверждение руководителем) — заглушку, зафиксированную как временную ещё в комментариях кода. Она не даёт ни постановки задачи, ни обсуждения, ни объективной проверки выполнения. PRD (`docs/salary-rule-bitrix-task/prd-salary-rule-bitrix-task.md`) фиксирует целевое решение: правило привязывается к реальной задаче Bitrix24, вся постановка и приёмка идут там, а iReports читает статус задачи для расчёта факта/прогноза зарплаты.

## What Changes

- Правило `TaskCompleted` в конструкторе схемы мотивации (сервис и магазин) получает новую форму: название, описание, расчётный месяц, вид (разовая/регулярная), дедлайн, сумма вознаграждения за полное выполнение — только для схем на сотрудника, не на отдел.
- При сохранении правила iReports создаёт задачу типа «Зарплатная задача» в Bitrix24 и хранит в правиле только `bitrixTaskId` + период (для регулярных — по ID на месяц); ошибка Bitrix24 откатывает сохранение схемы целиком.
- Расчёт факта/прогноза зарплаты читает статус и расчётный месяц задачи из Bitrix24 пакетным запросом (не по одной задаче на правило); закрытая задача даёт факт (с опциональной ручной частичной суммой), любой статус текущего месяца — прогноз.
- Руководитель может на странице зарплатного отчёта (открытый месяц) указать фактическую сумму по закрытой задаче (0..сумма правила); значение фиксируется в снапшоте при закрытии периода.
- Крон автосоздаёт задачу нового месяца для регулярных правил 1-го числа, идемпотентно (по аналогии с `SalesPlanAutoCreationCron`/`EnsureSalesPlansForPeriodService`).
- Удаление правила/схемы удаляет связанные задачи в Bitrix24; ошибка удаления в Bitrix24 блокирует удаление правила.
- На странице схемы мотивации и в зарплатном отчёте — ссылка на задачу в Bitrix24; недоступная/удалённая задача помечается «задача недоступна» и не даёт начисления.
- **BREAKING**: контракт `taskCompletedSalaryRuleSchema` меняется — вариант награды `FloatPercent` убирается, остаётся только фиксированная сумма.
- **BREAKING**: временный воркфлоу `TaskCompletion` (статусы `PENDING_CONFIRMATION`/`CONFIRMED`/`REJECTED`, эндпоинты `create/confirm/delete/list task_completions`, соответствующий UI) выводится из эксплуатации.

## Capabilities

### New Capabilities
- `service/salary-task-rule`: правило зарплаты `TaskCompleted`, привязанное к задаче Bitrix24 — создание/удаление задачи, чтение статуса и расчётного месяца, факт/прогноз, ручная частичная сумма, перенос месяца, автосоздание регулярных задач, ссылка на задачу, вывод из эксплуатации `TaskCompletion`.

### Modified Capabilities
_(нет — `TaskCompleted` в проекте ещё не описан отдельной спекой; текущая спека для него создаётся впервые как New Capability выше)_

## Impact

- `backend/src/domains/service/modules/accounting/domain/entities/salary-rules/task-completed.entity.ts` — переработка расчёта: источник — статус задачи Bitrix24, а не `TaskCompletion.status`.
- `backend/src/domains/service/modules/accounting/domain/entities/task-completion.entity.ts` и весь application/interface-слой `TaskCompletion` (`command/`, `http-controllers/`, `dto/`) — вывод из эксплуатации.
- `backend/src/integrations/bitrix/` — новые методы создания/обновления/удаления задач (`tasks.task.*`), пакетное получение статусов; новые типы в `bitrix-api.types.ts`.
- Новый крон по аналогии с `sales-plan-auto-creation.cron.ts` для автосоздания задач регулярных правил.
- `contracts/commands/salary-rule.ts`, `contracts/commands/task-completion.ts` — изменение/удаление схем.
- `frontend/src/features/SalaryRuleForm/{service,shop}/` — новая форма правила `TaskCompleted`; удаление UI отметки/подтверждения `TaskCompletion`.
- `frontend/src/pages/SalaryReportV2/` — ввод фактической суммы, ссылка на Bitrix24, пометка «задача недоступна».
- `prisma/schema/salary.prisma` — модель `TaskCompletion` выводится из эксплуатации (миграция/доработка открытых месяцев — решается в design.md); новая структура хранения `bitrixTaskId`/периода в правиле.
