## REMOVED Requirements

### Requirement: Создание задачи в Bitrix24 при создании зависимого зарплатного правила
**Reason**: Задача зарплатного правила «за выполнение задачи» больше не создаётся во внешней системе
— заменена собственной сущностью iReports (`tasks`, capability `tasks`).
**Migration**: Новая задача создаётся локально в iReports (`Requirement: Задача — самостоятельная
сущность iReports` в capability `tasks`), без обращения к Bitrix24.

### Requirement: Разовая и регулярная задача
**Reason**: Поведение «разовая/регулярная задача» сохраняется, но переносится на локальную сущность
— больше не относится к интеграции с Bitrix24.
**Migration**: См. `Requirement: Разовое и регулярное правило` в capability `tasks` — тот же контракт
без Bitrix24.

### Requirement: Двусторонняя синхронизация данных задачи
**Reason**: Синхронизировать больше нечего — задача не существует во внешней системе, поэтому push
дедлайна и поллинг статуса упраздняются вместе со всей интеграцией.
**Migration**: Изменение дедлайна и перевод в статус «Выполнено» происходят напрямую в iReports (см.
`Requirement: Редактирование задачи полностью локально` и `Requirement: Завершение задачи
ответственным сотрудником` в capability `tasks`) — без синхронизации, без задержки поллинга.

### Requirement: Закрытие связанной задачи при удалении зарплатного правила
**Reason**: Поведение «удаление правила закрывает задачу» сохраняется, но переносится на локальную
сущность — больше не относится к интеграции с Bitrix24.
**Migration**: См. `Requirement: Отмена правила отменяет незавершённую задачу` в capability `tasks`.

### Requirement: Учёт задач обоих направлений в общем хранилище
**Reason**: Общее хранилище задач обоих направлений сохраняется, но это больше не специфика
Bitrix-интеграции — единая сущность `tasks` по определению общая для всех направлений.
**Migration**: См. `Requirement: Задача общая для всех направлений бизнеса` в capability `tasks`.
