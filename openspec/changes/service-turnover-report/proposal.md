## Why

У направления «Сервис» нет отчёта по оборачиваемости товаров/запчастей: невозможно за один взгляд
увидеть расход и остаток по категориям справочника товаров (включая вложенные категории) и по
складам за месяц. Кастомный эндпоинт RoApp `POST /getGoodsFlowReport` уже отдаёт агрегаты
расход/остаток (шт и руб.) по категории и складам за период, но эти данные нигде в iReports не
собираются, не хранятся и не показываются пользователю в разрезе полного дерева категорий и складов.

## What Changes

- Новая интеграция с кастомным RoApp-эндпоинтом `POST /getGoodsFlowReport` (принимает `startDate`,
  `endDate`, `category_id`, `warehouses`; отдаёт `outcome.{quantity,sum}` и `stock.{quantity,sum}`) —
  клиент-порт в инфраструктуре синхронизации RoApp.
- Новый отчёт по оборачиваемости сервиса за месяц: расход и остаток товара (шт и ₽) по каждой
  категории и каждой вложенной категории справочника товаров, отдельно по каждому складу.
- По каждой позиции отчёта (категория × склад) дополнительно считается коэффициент оборачиваемости:
  `Оборот_₽(текущий месяц) / ((Остаток_₽(прошлый месяц) + Остаток_₽(текущий месяц)) / 2)` — считается
  в рублях (по сумме), а не в штуках.
- Построение отчёта обходит полное дерево категорий (все категории и все вложенные категории
  справочника) и все склады, запрашивая `getGoodsFlowReport` по каждой паре категория × склад за
  выбранный месяц.
- Просмотр отчёта за прошлые периоды (месяцы) — не только за текущий.
- Фоновый пересчёт отчёта текущего (открытого) месяца каждый час — новая крон-задача.
- Закрытие месяца останавливает пересчёт этого месяца и фиксирует (сохраняет) его данные как снэпшот;
  закрытый месяц больше не пересчитывается по расписанию. Самостоятельного действия «закрыть» у
  этого отчёта нет — закрытие происходит автоматически вместе с закрытием расчётного (зарплатного)
  периода направления «Сервис» за тот же месяц (переиспользуется существующая таблица
  `AccountingPeriod` и событие её закрытия, без своей отдельной таблицы периода).
- Новая синхронизация справочника складов из RoApp (в проекте пока нет ни модели, ни синка) —
  используется для построения и отображения отчёта. Дерево категорий товаров для этого не заводится
  заново: оно уже синхронизируется и хранится в БД (`RoappProductCategory`, есть иерархия
  parent/child).

## Impact

- **Backend**: новый модуль в `backend/src/domains/service/modules/` (или расширение
  `service/sync/roapp`) — клиент к `POST https://rm.murygin.tech/getGoodsFlowReport`, доменная
  логика построения/хранения отчёта, крон-задача ежечасного пересчёта (по аналогии с
  `roapp-sync.cron.ts`, `ProdCron`/`CronExpression`), обработчик существующего события закрытия
  расчётного периода (`AccountingPeriodClosedDomainEvent`) для фиксации снэпшота, новая Prisma-модель
  справочника складов и новая Prisma-модель строк отчёта по оборачиваемости (без отдельной таблицы
  периода — статус читается из уже существующей `AccountingPeriod`; дерево категорий переиспользует
  уже существующую `RoappProductCategory`), HTTP-эндпоинт для чтения отчёта за период.
- **Contracts** (`contracts/`): схемы запроса/ответа отчёта по оборачиваемости.
- **Frontend**: новая страница/раздел отчёта по оборачиваемости с деревом категорий, разбивкой по
  складам, выбором месяца/периода.
- **ENDPOINTS.md**: добавить новые backend-эндпоинты после реализации.
- **Внешняя зависимость**: доступность и стабильность кастомного RoApp-эндпоинта
  `getGoodsFlowReport` на `rm.murygin.tech`.
