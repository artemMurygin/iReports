## Ключевые состояния экранов

Структура согласована между брейкпоинтами: `App Bar`/`Bottom Nav` (мобайл) вместо `Topnav` (десктоп), но одинаковые смысловые блоки `Page Header` → `Filters`/`Filter Row` → контентная зона (`Ledger Table` или состояние-заглушка).

## Доработка таблицы: финальный паттерн «Ledger» (сделано пользователем напрямую в Pencil)

После промежуточной итерации (описанной ранее в этом документе — компактная строка 40px + отступ/тики-гиды с капом на уровне 3, реализовано поверх `Uv3ma`) пользователь взял работу над макетом в свои руки и полностью пересобрал таблицу в артборде **`WvSO6`** («Оборачиваемость · Альтернатива A «Ledger»»), одновременно спроектировав мобильные состояния. Старый артборд **`AsQo8` удалён**; `VzQy1` (закрытый месяц) обновлён до того же паттерна. Ниже — структура финальной версии, вычитанная напрямую из .pen-файла (`Get` со структурным обходом, не пересказ намерения):

### Высота строки: теперь 32px (строки верхнего уровня и шапка) / 28px (вложенные строки)
Дальнейшее уплотнение по сравнению с промежуточной итерацией (была единая высота 40px). Проверено `Get`+`ctx.bounds`/`ctx.problems` по всем строкам `Ledger Table` — переполнений и клиппинга нет.

### Вложенность категорий: `Rail`-паттерн, масштабируется на любое число уровней без капа
Внутри ячейки «Категория» каждой строки — цепочка из `N` фреймов **`Rail`** (по 16px, ровно по одному на каждый уровень предка: у строки уровня 0 рейлов нет, у строки уровня 3 — три рейла), затем `Marker` (небольшая метка/тире, обозначает саму строку) и `Label` — **только собственное имя категории** (не полный breadcrumb-путь, в отличие от промежуточной итерации). В реальных данных макета продемонстрировано 4 уровня: `Дисплеи` (0) → `iPhone` (1) → `OLED` (2) → `Оригинал` (3), аналогично `Корпусные детали` (0) → `Задние крышки` (1, нулевые показатели + `—` в коэффициенте, сохранена по `spec.md`) → `iPhone 14` (2). В отличие от промежуточной версии здесь нет фиксированного капа глубины — паттерн «один Rail на уровень» линейно продолжается на 5+ уровней без изменения логики (открытый вопрос — насколько широкой окажется колонка «Категория» на очень глубоких деревьях, см. «Открытые вопросы»).

### Итоговая строка и сводка
Над таблицей — строка **«Итого»** (84px), агрегирующая расход/остаток/коэффициент по всем категориям текущего фильтра — этого не было в промежуточной итерации.

### Мобильная версия (390) — тот же Ledger-паттерн
`yDBTb`/`RvLO7`/`XJH3r`/`akKcU`/`W9VKM` используют ту же структуру `Ledger Table`/`Loading State`/`Error State`/`Not Recalculated State`, что и десктоп, внутри `App Bar` → `Body` (`Page Header` → `Filters` → контент) → `Bottom Nav`.

В `uDEum` (UI Kit) новых компонентов не заведено — `Rail`/`Marker`/`Ledger Table` остаются page-local структурой конкретно этого экрана (не отдельные reusable-компоненты), как и было решено ранее.

## Новые компоненты UI Kit

Новых компонентов **внутри `uDEum`** не заведено — везде, где существовал подходящий компонент, он использован как `ref`-инстанс. Ниже — page-local композиции (в самом экране, не в `uDEum`), которые не являются переиспользуемыми компонентами уровня всего приложения, а специфичны для этой страницы (или ещё не набрали ≥2 использований, чтобы претендовать на UI Kit):

| Композиция | Node ID (page-local) | Где используется | Почему не в `uDEum` |
|---|---|---|---|
| Period Field (триггер выбора месяца: подпись «Период ·» + значение + `chevron-down`) | `wrXyr` (в `WvSO6`; в остальных артбордах — копии) | Filter Row всех состояний, десктоп и мобайл | Повторяет уже существующий в документе паттерн `rVa6H` "Field Период" (не входит в `uDEum`, тоже page-local для другого экрана) — тот же визуальный язык, но полноценного компонента с этим именем в UI Kit ещё нет; ре-регистрация в `uDEum` не входила в скоуп этой задачи (не менялся сам UI Kit) |
| Status Pill · Открыт / Закрыт (точка + текст статуса периода) | `QVydh` (открыт, `WvSO6`) / `Sk1nF` (закрыт, `VzQy1`) | Filter Row | Повторяет цветовую пару токенов из уже существующего в документе паттерна `kO7KN` "Period State" (`$info-soft`/`$info-ink` для закрытого) и `PGyPp`/`$brand-soft` для открытого — собрано заново как двухстрочная композиция (точка + текст), а не вынесено в `uDEum`, т.к. пока используется только на этом экране |
| Warehouse Select (склад, левая часть Filter Row) | `M6ZfP` (`WvSO6`) / `dGAXG` (`VzQy1`) / `yKcNQ` (`jxljA`) / `u6VEag` (`t7VF4`) / `t2Qsc` (`Q2EwKA`) | Filter Row всех 5 десктопных состояний | По итогам ревью (пользователь: «сделай селект, а не таб») переделан из `ERP/Molecule/Tabs` в select-подобное поле — тот же паттерн, что уже используется для Period Field (подпись + значение + `chevron-down`), а не новый визуальный язык |
| Category Filter Chip (левая часть Filter Row) | `On9ZZ` (в `WvSO6`) | Filter Row | См. примечание про `CategoryTreeSelect` ниже |
| Ledger Table — `Итого` (сводная строка с 3 мини-метриками), `Header Row`, строки `R1`…`R4` с `Rail`/`Marker`/`Категория` | `D3Sf4` (в `WvSO6`, корень таблицы) | Заполненные состояния, десктоп и мобайл | Табличная композиция специфична для этого отчёта (произвольная глубина дерева категорий) — не обобщалась в `uDEum`, см. «Доработка таблицы» |
| Loading / Error / Not-yet-recalculated блоки контентной зоны | `OEmFs` / `W2qBFM` / `S5rxTH` (десктоп); мобильные копии в `XJH3r`/`akKcU`/`W9VKM` | Соответствующие состояния | Построены по уже существующему в документе паттерну Empty State (`UlVij` — иконка в кружке + заголовок + описание [+ кнопка]), адаптированы под конкретный текст/цвет (`$danger-soft` для ошибки) — не универсальны настолько, чтобы обобщать в `uDEum` в рамках этой задачи |

**`WarehouseSelect` доработан по итогам ревью**: изначально (промежуточная и первая финальная итерация) был показан через `ref`-инстанс `ERP/Molecule/Tabs` (`wQOPI`) с фиксированными 3 табами — пользователь явно попросил заменить на селект («в проекте их полно»). Во всех 5 десктопных артбордах узел заменён (`Replace`, проверено `Get`+`ctx.problems` — пусто, скриншот `Filter Row` подтверждён визуально) на select-поле в том же визуальном языке, что уже применяется для Period Field: подпись «Склад ·» + текущее значение + `chevron-down`, без завязки на количество складов. Мобильные состояния (`yDBTb` и др.) уже с первой итерации использовали `Chip`-триггер для склада (а не Tabs), так что там доработки не потребовалось. Компонент в `uDEum` не заводился — переиспользован тот же page-local паттерн, что и у Period Field.

`CategoryTreeSelect` (фильтр по категории) показан в макете только в свёрнутом виде — `Chip`-триггер (`ref` на `sVWu5`, node `On9ZZ` в `WvSO6`) с меткой «Все категории». Разворачиваемое дерево-поповер отдельно не отрисовывалось: по `architecture.md` это переиспользование существующего React-компонента `pages/ServicesReport/ui/CategoryTreeSelect` (page-local порт под `pages/GoodsTurnoverReport/ui`), чья popover-структура уже реализована и не нуждается в повторном пиксель-в-пиксель мокапе.

## Отклонения от architecture.md

Отклонений от состава сущностей/полей `architecture.md` нет. Уточнения, сделанные в процессе дизайна (не меняют architecture.md, но фиксируются здесь):

- Мобильный breakpoint изначально не проектировался (см. предыдущую итерацию), но пользователь спроектировал его напрямую сам — теперь есть полный набор из 5 мобильных состояний (390), см. «Ключевые состояния». Открытый вопрос про мобильный снят.
- `WarehouseTabs` → **`WarehouseSelect`**: по прямому указанию пользователя компонент переключения склада — select-поле (тот же паттерн, что Period Field), а не Tabs. `architecture.md` обновлён (см. таблицу UI-компонентов); мокап приведён в соответствие во всех 5 десктопных состояниях.
- Артборд `AsQo8` (первая версия таблицы, промежуточная итерация) удалён пользователем и заменён финальным `WvSO6`/`VzQy1` («Ledger»-паттерн) — состав данных/полей не изменился, изменилось только визуальное решение таблицы.
- Глубина вложенности категорий в `Rail`-паттерне подтверждена пользователем как достаточная до 5 уровней — специального ограничения/капа сверх этого не вводится (см. «Открытые вопросы» — снято).
