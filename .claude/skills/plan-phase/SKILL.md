# Plan Generator

Прочитай PRD из фаила: $ARGUMENTS

Создай план реализации и сохрани в фаиле 'docs/$ARGUMENTS/pan-$ARGUMENTS.md' (используй kebab-case)

## Структура плана

# Plan: {название фичи}

**PRD** $ARGUMENTS
**Дата** {текущая дата}

## Фазы реализации

### Фаза 1: {название}
**Цель** Что дает эта фаза
**Что затрагивает?** backend / database / frontend / design
**Задачи:**
- [ ] Задача 1
- [ ] Задача 2
**Когда готово** Конкретный критерий

### Фаза 2: {название}
...

## Правила разбивки на фазы:
- Каждая фаза должна давать рабочий результат. 
- Фазы независимы, можно остановиться после любой.
- Первая фаза минимальный рабочий путь (Tracer Bullet)
- Не больше пяти задач в одной фазе
- Backend и Frontend одной фичи - разные фазы. 
- К каждой фазе должны быть запланированы тесты для проверки результатов работы

## Правила
- Считай PRD внимательно. 
- План должен покрывать все критерии готовности. 
- Не добавляй задачи, которых нет в PRD. 
- Если PRD не полный, задай вопрос перед созданием плана.
