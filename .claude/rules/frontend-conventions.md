# Frontend conventions

## Публичный API фичи через index.ts
`features/<Feature>/index.ts` реэкспортирует только корневой UI-компонент фичи.
Импортировать из фичи следует только через этот `index.ts`, не напрямую из `ui/` или `model/`.

## Запросы через query options factory
Запросы к backend оформляются не как обычные async-функции, а через объект `api` в
`model/api.ts`. Каждый метод возвращает `queryOptions({...})` из TanStack Query —
переиспользуемые типобезопасные `queryKey`/`queryFn` без дублирования между
`useQuery`, `prefetchQuery`, `invalidateQueries`.

## Нормализация ошибок API
Ошибки сети/API оборачиваются в `ApiError` (`shared/errors/apiError.ts`) прямо в `.catch()`
внутри `queryFn`, с человекочитаемым сообщением на русском. Компоненты читают
`queryError.message`, не работают с сырыми ошибками axios напрямую.

## Model-хуки с плоским состоянием
Хуки в `model/` инкапсулируют одну зону ответственности и возвращают плоский объект
состояния и обработчиков. Композиция нескольких хуков — на уровне страницы или
mediator-компонента; хуки не знают друг о друге.

## Mediator-компонент для страниц с несколькими виджетами
Страница, объединяющая несколько stateful-виджетов, использует отдельный `mediator/`-
компонент: вызывает нужные `model`-хуки, прокидывает результат в `ui`-компоненты, не
содержит собственной бизнес-логики — только оркестрацию.

Тот же принцип — на страницах с одним основным виджетом: весь стейт/обработчики в одном
`model/useXPage.ts`-хуке с плоским объектом на возврате, страница — чистая склейка
`useXPage()` → пропсы `Layout`.

Медиатор/страница не должен содержать условного рендера — такое ветвление выносится в
отдельный презентационный компонент.

## Слоты вместо children
Layout/контейнерные компоненты почти всегда принимают именованные слоты (`header`, `body`,
`footer`, `actions` — пропсы `ReactNode`) вместо единого `children`. Родитель собирает
контент для каждого слота отдельно и передаёт как обычные пропсы.

Если контент слота собирается из нескольких пропсов/компонентов — вычислять его в
переменную выше `return`, а не инлайнить в JSX-проп.

## isInitialLoad / isRefreshing вместо единого isLoading
В хуках аналитики состояние загрузки разделяется на:
- `isInitialLoad` — данных ещё нет, скелетон на весь блок
- `isRefreshing` — данные уже есть, идёт фоновый рефетч, лёгкий индикатор поверх старых данных

Вычисляются поверх `useQuery` с `placeholderData: keepPreviousData`. Использовать это
разделение там, где смена фильтров не должна "схлопывать" уже отрисованные данные.

## UI Kit и state management
Новые страницы и компоненты идут в новый UI Kit (`shared/ui-kit/`: `tokens/`, `atoms/`,
`organisms/`), а не в `shared/ui/` (shadcn-примитивы на старых токенах — только для уже
существующих, ещё не мигрированных страниц).

Паттерн, начавший повторяться в ≥2 страницах/фичах, выносится в `shared/ui/` вместо
копирования.

Для клиентского состояния — Zustand, только для бизнес-данных (не заводить лишние
зависимости от стора). Для серверного состояния — TanStack Query.
