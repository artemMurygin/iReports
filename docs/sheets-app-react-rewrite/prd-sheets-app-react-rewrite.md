# PRD: Переписать Google Sheets Interface на React в отдельном воркспейсе `sheets-app`

**Дата**: 2026-08-13
**Статус**: Draft

> ⚠️ **Важно**: ни один сценарий из этого PRD не проверялся вживую на реальной Google Таблице — самостоятельный запуск воздержан намеренно, так как боевая таблица содержит чувствительные данные (начисления мастеров, цены, привязку к RemOnline/МойСклад) и ошибочный вызов серверных функций может их повредить. Все критерии готовности, требующие проверки в реальной Таблице, должен выполнить и подтвердить сам пользователь.

## Цель

Текущий встроенный в Google Таблицу интерфейс (`frontend/GoogleSheetsInterface/index.html` + `index.gs`) — это один файл с 1160 строками инлайнового HTML/CSS/JS без сборки, типов и переиспользования кода. Нужно перенести его в полноценный React-проект `sheets-app` — отдельный npm-воркспейс монорепо, как `frontend`/`backend`/`contracts` — сохранив ту же функциональность и визуально эквивалентный дизайн (на компонентах shadcn/ui), а серверную часть (`index.gs`) переписать так, чтобы она продолжала работать как Apps Script backend того же самого встроенного в Таблицу приложения.

## Пользовательские сценарии

- Пользователь открывает Google Таблицу, вызывает меню «Таблица → МС / РЕМ → Запустить» -> открывается боковая панель с React-приложением (визуально эквивалентным нынешнему).
- Пользователь на вкладке «Мой склад» перетаскивает или выбирает xlsx/xls-файл прайса Trade-mi и нажимает «Загрузить прайс» -> файл уходит на backend, в панели показывается «стеклянный» лоадер с живым логом статусов через SSE-поток, по завершении — сообщение об успехе/ошибке.
- Пользователь на вкладке «Мой склад» нажимает «Обновить РЦ в МС» / «Обновить акционную РЦ в МС» / «Получить цены из МС» -> запускается соответствующая синхронизация с МойСклад, статус отображается под кнопками.
- Пользователь на вкладке «Ремонлайн» нажимает «Загрузить цены в RO» -> цены из листа начислений уходят в RemOnline, в таблицу пишутся старые цены, в панели отображается сводка (всего/валидных/создано/обновлено/ошибок).
- Пользователь на вкладке «Ремонлайн» нажимает «Обновить начисления мастеров» -> начисления подтягиваются из RemOnline и построчно сверяются/записываются в лист, показывается список обновлённых ID.
- Пользователь на вкладке «Ремонлайн» нажимает «Создать услуги в Ремонлайн» -> по всем строкам листа со значением «Создать» в столбце ID построчно создаются услуги в RemOnline, в столбец ID пишется либо ID созданной услуги, либо текст ошибки, показывается итоговая сводка (обработано/создано/ошибок).
- Пользователь нажимает «Добавить новую услугу» -> раскрывается каскадный выбор категории (дерево категорий из RemOnline), после выбора и нажатия «Записать категорию» путь категории пишется в активную ячейку листа.

## В скоупе

- Новый top-level каталог `sheets-app/` (на одном уровне с `frontend`, `backend`, `contracts`, `docs`, `design`), подключённый как npm-воркспейс корневого `package.json` монорепо.
- React + TypeScript + Vite SPA внутри `sheets-app`, собираемая в единый инлайновый HTML-файл (без внешних запросов к статике), пригодный для `HtmlService.createHtmlOutputFromFile` в Apps Script.
- Полное покрытие текущего функционала `index.html`:
  - вкладки «Мой склад» / «Ремонлайн»;
  - drag-and-drop загрузка xlsx/xls прайса с прогресс-логом через SSE (`EventSource` на `/v1/shop/marketing/pricing/import-costs/{uuid}`);
  - три кнопки синхронизации с МойСклад (обновить РЦ, обновить акционную РЦ, получить цены);
  - выгрузка цен в RemOnline со сводкой по счётчикам;
  - обновление начислений мастеров с построчной сверкой;
  - массовое создание услуг в RemOnline (валидация обязательных полей, построчная обработка, запись ID/ошибки обратно в лист);
  - каскадный выбор категории (дерево из RemOnline) и запись пути категории в активную ячейку;
  - «стеклянный» лоадер с анимацией и логом шагов, тултип с подсказкой по обязательным полям.
- Визуально эквивалентный дизайн, реализованный на компонентах shadcn/ui (та же цветовая схема: зелёный `#4CAF50`/`#2e7d32` для «Мой склад»-действий, синий `#2955af` для «получить»-действий, оранжевый `#e65100` для создания услуг; тот же layout вкладок, дропзоны, лоадера, сводок).
- Слой-обёртка над `google.script.run` (типизированный клиент для вызова серверных функций Apps Script из React) с возможностью подмены моками для локальной разработки вне контекста Google Таблицы.
- Переписанная/зарефакторенная серверная часть (аналог сегодняшнего `index.gs`) внутри `sheets-app`, сохраняющая тот же набор серверных функций и их поведение: обращения к `BASE_URL` (`https://api.murygin.tech`) и n8n-вебхукам, чтение/запись листа начислений по тем же столбцам (`ACCRUALS_SHEET_GID`, столбцы E/AW/BH/BS и т.д.), логика создания услуг.
- Сборочный пайплайн, объединяющий фронтенд-бандл и серверный Apps Script код в структуру, готовую к деплою через `clasp push` в тот же существующий Apps Script проект, привязанный к боевой Google Таблице.
- Удаление каталога `frontend/GoogleSheetsInterface` после того, как функциональность подтверждена работающей из `sheets-app` (старая реализация не остаётся дублем).

## Не в скоупе

- Изменение серверного REST API (`backend/`, эндпоинты `/v1/shop/marketing/pricing/...`, `/v1/service/marketing/pricing/...`, `/roapp/...`, `/custom-api-roapp/...`) и n8n-вебхуков — их контракты используются как есть, без изменений.
- Новые фичи, которых нет в текущем интерфейсе (доп. вкладки, новые интеграции, новые действия).
- Публикация приложения как самостоятельного Web App (`doGet`, публичный URL вне Таблицы) — сегодня интерфейс работает только как боковая панель (`showSidebar`), этот режим и сохраняется.
- Автоматический прод-деплой (`clasp push`/`clasp deploy`) в существующий `scriptId`, привязанный к боевой Таблице, через CI/CD — сам деплой в Apps Script в этой итерации остаётся ручным/локальным действием пользователя, без approval-гейта и без staging-копии Таблицы это небезопасно (см. предупреждение в начале документа). CI может линтить/собирать/типизировать `sheets-app` на каждый PR, но не должен автоматически пушить в прод-скрипт.
- Поддержка нескольких Google Таблиц/нескольких Apps Script проектов одним кодом — миграция касается ровно той таблицы и того привязанного скрипта, что использует `GoogleSheetsInterface` сегодня.
- Локализация интерфейса — как и сейчас, только русский язык.
- Тестовое покрытие (unit/e2e) серверных `.gs`-функций — Apps Script рантайм не поддерживается стандартными раннерами монорепо; это отдельный вопрос вне данной итерации.

## Технические ограничения

- `HtmlService` Apps Script отдаёт только один статичный HTML-файл без отдельных JS/CSS-ассетов — фронтенд обязан собираться в единый файл (например, `vite-plugin-singlefile`), с ограничением на итоговый размер (Apps Script квотирует размер контента `HtmlService`).
- `google.script.run` — асинхронный callback-based API, доступный только внутри реального контекста Apps Script (боковая панель/диалог, открытая из Таблицы) — локальная разработка требует слоя моков поверх этого API.
- Существующий Apps Script проект уже привязан (`scriptId`) к конкретной боевой Google Таблице и содержит хардкод специфичных для неё координат листа (`ACCRUALS_SHEET_GID`, номера столбцов E/G-N/AW/AY/BH/BS/BU) — рефакторинг серверной части не должен менять эти внешние контракты и обязан деплоиться в тот же `scriptId`, а не создавать новый Apps Script проект.
- `sheets-app` подключается как npm-воркспейс монорепо и переиспользует общий tooling (ESLint/Prettier/TypeScript-конфигурации) по аналогии с `frontend`, но при этом использует компоненты shadcn/ui для визуального паритета — доля переиспользования UI-кита `frontend/src/shared/ui` (те же примитивы shadcn) или собственный набор компонентов в `sheets-app` — уточняется на этапе реализации.
- Приложение не имеет собственной серверной сессии/БД — всё состояние живёт в самой Google Таблице и во внешних системах (МойСклад, RemOnline, backend `api.murygin.tech`), поэтому React-часть остаётся тонким UI-слоем без клиентского стора данных сверх состояния текущей сессии панели.
- Автоматический CI/CD-деплой (`clasp push`/`clasp deploy`) в Apps Script технически возможен (например, через GitHub Actions с OAuth-креды `clasp` в секретах), но в этой итерации сознательно не делается: единственный существующий `scriptId` привязан к боевой Таблице с чувствительными данными, и автопуш без staging-окружения повышает риск случайно сломать прод при мёрдже. Если понадобится автодеплой в будущем, потребуется отдельная тестовая копия Таблицы/скрипта под staging — это отдельная задача вне текущего скоупа.

## Критерии готовности

- [ ] В корне репозитория существует каталог `sheets-app/`, подключённый как npm-воркспейс (виден в `npm ls --workspaces` из корня).
- [ ] React SPA из `sheets-app` собирается в единый HTML-файл, пригодный для `HtmlService.createHtmlOutputFromFile`.
- [ ] Обе вкладки («Мой склад», «Ремонлайн») реализованы на shadcn/ui и визуально эквивалентны текущему интерфейсу (цветовая схема, лоадер, тултип, сводки, дропзона сохранены).
- [ ] Загрузка прайса с drag-and-drop и отображением прогресса через SSE работает end-to-end в открытой из Таблицы боковой панели.
- [ ] Все три кнопки синхронизации с МойСклад («Обновить РЦ», «Обновить акционную РЦ», «Получить цены») работают и показывают статус как в текущей версии.
- [ ] Выгрузка цен в RemOnline пишет старые цены обратно в лист и показывает сводку по счётчикам (всего/валидных/создано/обновлено/ошибок).
- [ ] Обновление начислений мастеров построчно сверяет и обновляет лист, показывает список обновлённых ID.
- [ ] Массовое создание услуг в RemOnline обрабатывает все строки со значением «Создать», пишет ID/ошибку в столбец ID, показывает итоговую сводку.
- [ ] Каскадный выбор категории загружает дерево категорий из RemOnline и корректно пишет выбранный путь в активную ячейку.
- [ ] Серверные Apps Script функции сохраняют прежние внешние контракты (те же URL `BASE_URL`/n8n-вебхуков, те же координаты листа начислений) и задеплоены в тот же существующий `scriptId`.
- [ ] Приложение вручную проверено пользователем (не автономно ИИ-агентом — во избежание риска повредить чувствительные боевые данные) внутри реальной Google Таблицы: боковая панель открывается из меню «Таблица → МС / РЕМ → Запустить», все сценарии выше пройдены без регрессий.
- [ ] Каталог `frontend/GoogleSheetsInterface` удалён из репозитория после подтверждения работоспособности `sheets-app`.
