# PRD: Drag-and-drop переупорядочивание строк плана продаж

**Дата**: 2026-09-03
**Статус**: Draft

## Цель

Дать пользователям возможность вручную задавать порядок строк-категорий плана продаж через drag-and-drop в модалке редактирования плана, при этом заданный порядок должен быть общим для всех — единым для любого пользователя, а не персональным, и отражаться на странице плана продаж.

## Пользовательские сценарии

- Пользователь открывает модалку редактирования плана продаж (EditPlanModal) → видит строки-категории в текущем сохранённом порядке.
- Пользователь перетаскивает строку в таблице модалки (EditPlanTable) на новую позицию → строка визуально перемещается внутри модалки.
- Пользователь нажимает "Сохранить" в модалке → новый порядок вместе с остальными изменёнными полями плана сохраняется на сервере.
- Пользователь закрывает модалку кнопкой "Отмена" (или крестиком) после перетаскивания → изменение порядка не сохраняется, при повторном открытии модалки и на странице плана продаж отображается прежний порядок.
- Пользователь открывает страницу плана продаж (SalesPlanTable) → строки-категории отображаются в порядке, ранее сохранённом через модалку.
- Другой пользователь открывает модалку редактирования или страницу плана продаж (то же направление и подразделение) → видит тот же изменённый порядок строк.
- Пользователь переключается на другой расчётный период (месяц) для тех же категорий → видит порядок, ранее заданный для этих категорий, а не порядок по умолчанию.
- Пользователь на мобильной версии открывает список плана продаж → видит категории в том же сохранённом порядке, но без возможности перетаскивания.
- При сохранении модалки обрывается соединение → пользователь видит сообщение об ошибке, модалка остаётся открытой с текущим (ещё не сохранённым) порядком, чтобы попытку можно было повторить.

## В скоупе

- Drag-and-drop изменение порядка строк-категорий в таблице модалки редактирования плана (EditPlanTable внутри EditPlanModal).
- Сохранение нового порядка на сервере при подтверждении изменений в модалке (по нажатию кнопки сохранения), вместе с остальными правками плана.
- Отмена изменения порядка при закрытии модалки без сохранения.
- Единый (глобальный) порядок строк для всех пользователей — без персональных настроек сортировки.
- Порядок хранится на уровне категории и направления, а не привязан к конкретной месячной записи плана, и переносится между расчётными периодами для одних и тех же категорий.
- Отражение сохранённого порядка на странице плана продаж (десктопная таблица SalesPlanTable) и в мобильной карточной раскладке — в режиме чтения, без drag-and-drop там.
- Определение позиции для категории, ранее отсутствовавшей в сохранённом порядке (например, впервые появившейся в плане): такая категория добавляется в конец списка.
- Сообщение об ошибке при неудачном сохранении порядка вместе с остальными изменениями модалки.

## Не в скоупе

- Drag-and-drop на странице плана продаж (SalesPlanTable) вне модалки редактирования.
- Ручная сортировка / drag-and-drop в мобильной карточной раскладке.
- Персональные (per-user) настройки порядка строк.
- Введение ролевых ограничений на то, кто может менять порядок — сохраняется текущая модель доступа (без RBAC) для плана продаж.
- Одновременное отображение и сортировка нескольких подразделений на одной странице/в одной модалке.
- История изменений порядка (кто и когда менял, версии порядка).
- Групповое переупорядочивание нескольких выделенных строк одним перетаскиванием.

## Технические ограничения

- В текущей модели `SalesPlan` (Prisma) и в контракте `salesPlanSchema` отсутствует поле порядка/веса — потребуется его ввести.
- Уникальный ключ строки плана — `[direction, departmentId, categoryId, period]`: `id` конкретной строки меняется каждый месяц, поэтому сохранённый порядок должен переживать создание новых месячных записей для тех же категорий.
- Модалка редактирования (`useEditPlanForm`) сейчас сохраняет только изменённые поля (turnover/margin/orderTypeIds) по отдельным строкам — потребуется расширить сценарий сохранения так, чтобы изменение порядка сохранялось вместе с остальными правками за одно действие пользователя.
- Drag-and-drop библиотека (`@dnd-kit/core`, `@dnd-kit/sortable`, `@dnd-kit/utilities`) уже установлена в зависимостях фронтенда, но нигде в проекте не используется — реализация станет первым прецедентом.
- На бэкенде нет ролевой модели/guard'ов для эндпоинтов плана продаж — сохранение порядка будет доступно так же, как и остальные операции редактирования плана.
- Модуль `sales` продублирован для доменов `service` и `shop` (отдельные HTTP-контроллеры при общих command/handler классах) — изменения нужно синхронно поддержать в обоих наборах контроллеров и DTO.
- Нужно определить, должно ли изменение порядка блокироваться при закрытом расчётном периоде (`AccountingPeriod`), как это сделано для остального редактирования плана.

## Критерии готовности

- [ ] В таблице модалки редактирования плана (EditPlanTable) строки-категории можно перетаскивать мышью, меняя их порядок.
- [ ] Новый порядок сохраняется на сервере только при подтверждении изменений в модалке (нажатии кнопки сохранения), вместе с остальными изменёнными полями плана.
- [ ] Закрытие модалки без сохранения (отмена/крестик) не изменяет порядок строк — при следующем открытии отображается прежний порядок.
- [ ] После сохранения новый порядок отображается на странице плана продаж (десктопная таблица) без перезагрузки страницы.
- [ ] Порядок, заданный одним пользователем через модалку, виден всем остальным пользователям на странице плана продаж и в модалке редактирования (то же направление и подразделение).
- [ ] Порядок сохраняется при переходе между расчётными периодами (месяцами) для одних и тех же категорий.
- [ ] Категория, ранее отсутствовавшая в сохранённом порядке, отображается в конце списка, не нарушая порядок существующих категорий.
- [ ] Мобильная карточная раскладка отображает категории в том же сохранённом порядке, без возможности drag-and-drop.
- [ ] При ошибке сохранения порядка вместе с остальными изменениями модалка остаётся открытой, показывает сообщение об ошибке и сохраняет введённые пользователем изменения.
- [ ] Изменение порядка строк не влияет на статус утверждения (approved) и другие поля строк плана.
