# Plan: Новый UI Kit и компонент хедера (десктоп + мобильная версия)

**PRD**: Создать новую папку с UI Kit для использования на всех новых страницах фронтенда; создать компонент нового хедера (десктопная и мобильная версии) на основе дизайна в Pencil (`design/sallary-first-iteration.pen`, фрейм `uDEum` «ERP · UI Kit (Atomic)»), Node IDs: `C19pWf` (Scrim), `J7p0C` (App Bar), `SHMkH` (Subnav), `NoQNT` (Nav Bar).
**Дата**: 2026-08-14

## Что нашлось в дизайне (справочно, для реализации)

- Файл `design/sallary-first-iteration.pen`, фрейм `uDEum` «ERP · UI Kit (Atomic)» — полноценный референс UI Kit'а: `01 Foundations` (палитра, типографика, радиусы/сетка), `02 Atoms`, `03 Molecules`, `04 Organisms`, `05 Mobile`, `06 Правила`. Это основной источник для Фазы 1.
- Новые дизайн-токены (переменные .pen, без префикса `--`, не пересекаются с текущими shadcn-токенами `--background/--primary/...`): `brand`, `brand-strong`, `brand-foreground`, `brand-soft`, `brand-border`, `ink`, `ink-muted`, `canvas`, `surface`, `hairline`, `warn`, `warn-soft`, `danger`, `danger-soft`, `font-display`, `font-ui`, `ok-ink`, `warn-ink`, `row-selected`, `ink-faint`, `scrim`. Поддерживаются темы `Mode: Dark`, `Base: Gray/Stone/Zinc/Slate`, `Accent: Red/Rose/Orange/Green/Blue/Yellow/Violet` — для этой задачи реализуем только дефолтную комбинацию (светлая тема + дефолтный base/accent), остальное — задел на будущее.
- Хедер состоит из двух независимых собранных компонентов:
  - **Десктоп** — `dRfe8` (`ERP/Organism/Topnav`, 1440×104), включает `NoQNT` Nav Bar (56px: логотип+«iRepair», разделитель, секции навигации «Продажи/Аналитика/Зарплата/График работы», колокольчик с индикатором непрочитанных, разделитель, блок пользователя — аватар/имя/роль/«ещё») и `SHMkH` Subnav (48px: табы «Воронка продаж/План продаж»).
  - **Мобильная** — `kXibe` (`ERP/Mobile/App Bar`, 390×52): слева — кнопка меню (бургер) + хлебная крошка «раздел/страница», справа — 2 экшн-кнопки, колокольчик, аватар профиля. `C19pWf` (Scrim, 390×844) — затемняющая подложка, которая появляется поверх контента при открытии мобильного меню/шторок.
  - Раскрывающиеся меню профиля/уведомлений и содержимое мобильного drawer (`ERP/Organism/Menu Профиль`, `ERP/Organism/Menu Уведомления`, боковой Nav-drawer) в переданный набор Node ID не входят — в этой фиче хедер реализуется с рабочими триггерами (открыт/закрыт), но без содержимого выпадающих панелей. Это отдельная последующая задача.

## Фазы реализации

### Фаза 1: Скелет нового UI Kit + токены (tracer bullet)
**Цель**: Завести отдельную от `shared/ui` папку с новым дизайн-языком и довести один компонент (Button) от токена до рендера в браузере — доказать, что связка «Pencil-токены → Tailwind → React-компонент» работает целиком.
**Что затрагивает?** frontend
**Задачи:**
- [x] Создать папку `frontend/src/shared/ui-kit/` (подпапки `tokens/`, `atoms/`) — новый набор, не трогающий существующие файлы `shared/ui/*`
- [x] Перенести токены из фрейма `01 Foundations` (`uDEum` → `KXQ2P` Палитра, `u71Qo` Типографика, `T7KesB` Радиусы и сетка) в `frontend/src/shared/ui-kit/tokens/theme.css` через Tailwind v4 `@theme`, используя ровно те имена переменных, что в .pen-файле (`brand`, `ink`, `canvas`, `surface`, `hairline`, `warn`, `danger`, `scrim`, `font-display`, `font-ui` и т.д.), чтобы не конфликтовать с текущими `--primary`/`--background`
- [x] Подключить `theme.css` в сборку (импорт рядом с текущим `index.css`, без замены существующих токенов)
- [x] Реализовать `frontend/src/shared/ui-kit/atoms/Button.tsx` по компоненту `AP9Nr` (`ERP/Atom/Button`) на новых токенах
- [x] Временно вывести кнопку на любую существующую страницу (или тестовый роут) для визуальной проверки
**Когда готово**: `npm run build` и `npm run lint` проходят без ошибок; кнопка из `ui-kit/atoms/Button.tsx` рендерится в браузере и визуально соответствует скриншоту `AP9Nr` из Pencil (сверено через `mcp__pencil__get_screenshot`); существующие страницы и их стили не изменились. **Готово.** Токены живут в `frontend/src/shared/ui-kit/tokens/theme.css` (namespaced как `--uikit-*` → `@theme inline` под публичными именами), подключены через `frontend/src/index.css`; шрифт `font-display` потребовал добавить зависимость `@fontsource-variable/montserrat`. Превью — дев-роут `/ui-kit-preview` (вне `<Layout>`), страница `frontend/src/pages/UiKitPreview/`.

### Фаза 2: Атомы, необходимые для хедера
**Цель**: Собрать в `ui-kit` только те атомы, без которых нельзя построить хедер — по одному разу, переиспользуя их в десктопной и мобильной версии.
**Что затрагивает?** frontend
**Задачи:**
- [x] `ui-kit/atoms/IconButton.tsx` по `qVdml` (`ERP/Atom/Icon Button`) — для бургер-меню и экшн-кнопок мобильного App Bar

- [x] `ui-kit/atoms/BellBadge.tsx` по `wRlAq` (`ERP/Atom/Bell Badge`) — колокольчик с индикатором непрочитанных

**Когда готово**: каждый атом отрендерен рядом с временной кнопкой из Фазы 1 и визуально сверен со своим узлом в Pencil; `npm run build`/`npm run lint` без ошибок. **Готово.**

### Фаза 3: Хедер — десктопная версия
**Цель**: Рабочий десктопный хедер (Nav Bar + Subnav), пригодный для использования на новых страницах.

### Фаза 4: Хедер — мобильная версия и переключение
**Цель**: Мобильный App Bar со Scrim-подложкой и единая точка входа `Header`, переключающая десктоп/моб. вёрстку по брейкпоинту.
**Что затрагивает?** frontend
**Задачи:**
- [x] `ui-kit/organisms/Header/HeaderMobile.tsx` по `kXibe`: слева — `IconButton` (бургер) + хлебная крошка (раздел/страница текстом), справа — 2 экшн-кнопки, `BellBadge`, `Avatar`
- [x] `ui-kit/organisms/Header/Scrim.tsx` по `C19pWf`: полноэкранная затемняющая подложка с состоянием `open`, показывается поверх контента при открытии мобильного меню (без содержимого самого drawer'а — только визуальный оверлей и закрытие по клику)
- [x] `ui-kit/organisms/Header/Header.tsx`: единая точка входа, переключающая `HeaderDesktop`/`HeaderMobile` по Tailwind-брейкпоинту, управляет общим состоянием открытости мобильного меню (для `Scrim`)
- [x] Экспорт `Header` через `ui-kit/organisms/Header/index.ts` как единственную публичную точку входа модуля
**Когда готово**: на ширине 375px виден мобильный App Bar, визуально соответствующий скриншоту `kXibe`; открытие бургер-меню показывает `Scrim` (сверено со скриншотом `C19pWf`) и закрывается по клику на подложку; при изменении ширины окна хедер переключается между версиями без визуальных разрывов; `npm run build`/`npm run lint` без ошибок. **Готово** — лично перепроверено на 390×844 (мобильный App Bar, открытие/закрытие Scrim по клику).

- **Боковое мобильное меню** — добавлен `shared/ui-kit/organisms/Header/NavDrawer.tsx` по узлу `UiFMw` («Drawer», 320px: шапка с лого/крестиком + сгруппированный список разделов + подвал с пользователем), которого не было в исходном наборе Node ID. Подключён в `Header.tsx` поверх `Scrim`; клик по пункту меню теперь также закрывает drawer после навигации.
- **`user`/`subnavTabs` стали опциональными** на `HeaderDesktop`/`HeaderMobile`/`NavDrawer`/`Header` — в реальном приложении пока нет источника данных о текущем пользователе (нет `/me`-эндпоинта, нет auth-контекста на фронте), поэтому вместо вымышленной личности эти блоки (аватар/имя/роль/кнопка выхода) просто скрываются, пока не появится настоящая авторизация.
- **`disabled` для пунктов навигации** — добавлено на `HeaderNavItem`/`NavDrawerItem`, рендерится как некликабельный приглушённый пункт (перенос поведения старого `app/Header.tsx` для ещё не реализованных страниц).
- **Новый `Header` подключён как хедер всего приложения**: `frontend/src/app/Header.tsx` переписан — оборачивает `shared/ui-kit/organisms/Header` с реальными пунктами навигации (`/` Воронка продаж, `/services` Аналитика услуг, `/salaries` Отчёт по зарплатам — disabled, страница ещё не реализована) и мобильной хлебной крошкой, вычисляемой из текущего роута. `app/Layout.tsx`/`router.tsx` не менялись — `Header` там импортировался по имени и подключился прозрачно. Добавлена `sticky` позиция хедера (была у старого хедера, иначе была бы регрессия).
- Живьём проверено на реальных страницах `/` и `/services` (не только `/ui-kit-preview`): активные состояния по роуту, disabled-пункт, мобильный drawer открывается/закрывается и автозакрывается при переходе по ссылке.
- В `frontend/CLAUDE.md` добавлена заметка: все новые страницы/компоненты — в `shared/ui-kit/`, `shared/ui/` больше не расширяется новыми компонентами.

Мобильная хлебная крошка теперь показывает и раздел, и страницу (`section`/`page`). Секция целиком становится disabled, если disabled все её дочерние пункты (сейчас — «Зарплата»).

Дропдаун полностью убран; `HeaderNavItem` вернулся к плоской форме (`label/to/icon/end/disabled` + декоративный `chevron?`); добавлен `disabled` в `SubnavTab`, чтобы показывать ещё не готовые вкладки второго уровня (например, «План продаж» под «Продажи»). `app/Header.tsx` теперь строит плоские пункты верхнего уровня (по одному на раздел, ссылка на первую доступную дочернюю страницу) и отдельно вычисляет `subnavTabs` для активного раздела (показывается только если у раздела больше одной дочерней страницы).
