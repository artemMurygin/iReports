# PRD: Единый порядок сотрудников и фильтр служебных аккаунтов в зарплате

**Дата**: 2026-09-03
**Статус**: Draft

## Цель

Сейчас порядок отображения сотрудников определяется отдельно на каждой странице (где-то по алфавиту, где-то по id), поэтому один и тот же список выглядит по-разному в разных разделах. Нужно, чтобы порядок задавался вручную один раз и одинаково применялся везде, где есть список сотрудников. Отдельно — часть отделов заводит служебные аккаунты (не реальных сотрудников) для технических целей, и их нужно уметь полностью исключать из зарплатных данных, не удаляя из системы.

## Пользовательские сценарии

- Пользователь перетаскивает сотрудников в новом порядке на странице «График работы» → новый порядок сохраняется на бэкенде и сразу становится виден всем пользователям на всех страницах со списком сотрудников.
- Пользователь без специальных прав (любой авторизованный) меняет порядок → изменение применяется, без запроса дополнительных разрешений.
- Администратор открывает страницу настроек и отмечает сотрудника как «служебный» → сотрудник перестаёт попадать в отчёт по зарплате, взаиморасчёты/баланс, зарплатные схемы и справочник выбора сотрудника при создании отчёта (ни в списки, ни в расчёты, ни в итоговые суммы).
- Администратор снимает отметку «служебный» с сотрудника → сотрудник снова появляется во всех зарплатных выборках.
- Пользователь, не работающий с зарплатой, открывает график работы или страницу связей сотрудников → служебные сотрудники по-прежнему видны там, фильтр их не скрывает.

## В скоупе

1. Локальное поле порядка (order/weight) в сущности сотрудника (`BitrixEmployee`), не зависящее от синхронизации с Bitrix24 и не перезатираемое ею.
2. API для чтения текущего порядка сотрудников и сохранения нового порядка после ручного изменения.
3. Drag-n-drop изменение порядка сотрудников на странице «График работы».
4. Единый порядок сотрудников применяется на всех страницах со списком/справочником сотрудников: отчёт по зарплате (SalaryReportV2), взаиморасчёты/баланс сотрудника, график работы, список и редактор зарплатных схем (SalaryRuleList/SalaryRuleDetail), страница связей сотрудников (EmployeeIdentity), справочник выбора сотрудника при создании отчёта (`GET /v1/directory/employees`).
5. Менять порядок может любой авторизованный пользователь платформы, без отдельных прав/ролей.
6. Локальный признак «служебный аккаунт» в сущности сотрудника, независимый от флага `isActive` (который означает «уволен») и не перезатираемый синхронизацией с Bitrix24.
7. Интерфейс на странице настроек: список всех сотрудников с переключателем «исключить из зарплаты» для каждого.
8. Сотрудники, отмеченные как служебные, полностью исключаются из зарплатного раздела: отчёт по зарплате, взаиморасчёты/баланс, зарплатные схемы, справочник выбора сотрудника при создании отчёта — не попадают ни в списки выбора, ни в расчёты, ни в итоговые суммы.
9. Служебные сотрудники продолжают отображаться во всех разделах вне зарплаты (график работы, связи сотрудников и т.д.) — отметка скрывает их только из зарплаты, не деактивирует и не удаляет.

## Не в скоупе

- Права/роли, ограничивающие круг лиц, которые могут менять порядок сотрудников.
- История изменений порядка и признака «служебный» (аудит кто и когда поменял).
- Массовое редактирование порядка (импорт/экспорт весов через файл).
- Разный порядок сотрудников для разных отделов/страниц — порядок один и глобальный.
- Автоматическая пересортировка по другим критериям (стаж, отдел и т.д.), заменяющая ручной порядок.
- Скрытие служебных сотрудников за пределами зарплатного раздела.

## Технические ограничения

- Сегодня разные страницы получают список сотрудников из разных backend-эндпоинтов с собственной сортировкой (`orderBy: lastName/firstName asc` в справочнике, `orderBy: employeeId asc` в начислениях) — все они должны быть приведены к сортировке по единому полю order/weight.
- `BitrixEmployee` — сущность, синхронизируемая из Bitrix24; добавляемые поля (order/weight и признак «служебный») должны быть чисто локальными и не входить в цикл синхронизации.
- Нужна стратегия хранения весов, устойчивая к одновременному изменению порядка разными пользователями (без потери промежуточных изменений при параллельном перетаскивании).

## Критерии готовности

- [ ] В сущности сотрудника есть сохраняемое поле порядка (order/weight), не зависящее от синхронизации с Bitrix24
- [ ] Изменение порядка сотрудников через drag-n-drop на странице «График работы» сохраняется на бэкенде
- [ ] После изменения порядка тот же порядок отображается на: отчёте по зарплате, странице взаиморасчётов/баланса, графике работы, списке и редакторе зарплатных схем, странице связей сотрудников, справочнике выбора сотрудника при создании отчёта
- [ ] Любой авторизованный пользователь может изменить порядок без запроса дополнительных прав
- [ ] В сущности сотрудника есть сохраняемый признак «служебный аккаунт», не зависящий от синхронизации с Bitrix24 и от флага `isActive`
- [ ] На странице настроек отображается список сотрудников с возможностью отметить/снять отметку «служебный» для каждого
- [ ] Сотрудник, отмеченный как служебный, отсутствует в отчёте по зарплате, во взаиморасчётах/балансе, в зарплатных схемах и в справочнике выбора сотрудника при создании отчёта — ни в списках, ни в расчётах, ни в итоговых суммах
- [ ] Сотрудник, отмеченный как служебный, по-прежнему отображается в графике работы и на странице связей сотрудников
- [ ] Снятие отметки «служебный» возвращает сотрудника во все зарплатные выборки без дополнительных действий
