# Plan: Детализация начисления зарплаты — название проданного товара/услуги и ссылка на документ ERP

**PRD**: [docs/salary-accrual-source-item-detail/prd-salary-accrual-source-item-detail.md](./prd-salary-accrual-source-item-detail.md)
**Дата**: 2026-08-24

## Фазы реализации

### Фаза 1: Backend — название услуги в правиле "Оплата за услугу" (service)
**Цель**: Tracer bullet — минимальный сквозной путь: от данных RemOnline до ответа API, для одного правила одного направления.
**Что затрагивает?** backend, contracts
**Задачи:**
- [ ] Добавить опциональное поле названия товара/услуги в `calculationSourceRefSchema`/`employeeSalaryReportSourceSchema` (`ireports-contracts`), общее для service и shop.
- [ ] Расширить select в `ServiceCalculationDataRepository.findServiceCompletedItems` — добавить `service.name`, прокинуть в `ServiceCompletedErpItem`.
- [ ] Прокинуть название услуги из `ServiceCompletedEntity.buildSources` в `CalculationSourceRef`.
- [ ] Обновить маппер `to-salary-report-rules.ts`, чтобы поле попадало в `EmployeeSalaryReportSource`.
- [ ] Тесты: `service-completed.entity.spec.ts`, тест маппера `to-salary-report-rules.ts`, regression `get-employee-salary-report.service.spec.ts`.

**Когда готово**: `GET /v1/service/accounting/salary_report/employee/:id/:period` возвращает название услуги в `source` для правила `ServiceCompleted`; все существующие тесты проходят, новые тесты на поле — зелёные.

### Фаза 2: Frontend — отображение названия услуги (service)
**Цель**: Пользователь видит название услуги вместо родового "Позиция" на странице зарплатного отчёта, для направления service.
**Что затрагивает?** frontend
**Задачи:**
- [ ] Обновить компонент детализации источников начисления на `/salaries` (`RuleSourcesRail`/`AccrualLineSources`) — использовать новое поле названия услуги, когда оно есть; сохранить fallback на текущий generic-лейбл (`getSourceTypeLabel`) там, где поля нет.
- [ ] Обновить типы source на фронтенде под новое опциональное поле контракта.
- [ ] Проверить, что ссылка на заказ RemOnline и данные устройства (бренд/модель/цвет) продолжают отображаться как раньше.
- [ ] Ручная проверка в браузере: открыть `/salaries` для сотрудника с начислениями по правилу "Оплата за услугу", убедиться, что видно название услуги.
- [ ] Тесты: компонентный/снапшот-тест детализации источников с новым полем (если в проекте принят такой паттерн UI-тестов).

**Когда готово**: на `/salaries` в раскрытой детализации правила "Оплата за услугу" отображается название услуги; ссылка на заказ RemOnline и остальные правила (`OrderPayed`, `PayPerHour`, `TaskCompleted`) визуально не изменились.

### Фаза 3: Backend — название товара и ссылка на документ в правилах "продажа товара" (shop)
**Цель**: Сквозной путь от данных МойСклад до ответа API для правил `ProductSold` и `UsedProductSold`.
**Что затрагивает?** backend
**Задачи:**
- [ ] Добавить поля названия товара/устройства и id документа отгрузки в `ShopProductSoldErpItem` (`domain/types`).
- [ ] Прокинуть эти поля из источника данных shop-калькуляции (название товара/варианта из МойСклад, `demandId`).
- [ ] Создать builder ссылки на документ отгрузки МойСклад (аналог `buildRoappOrderLink` у service), уточнив формат URL карточки отгрузки.
- [ ] Обновить `ProductSoldEntity.buildSources` и `UsedProductSoldEntity.buildSources` — включить название и ссылку в `CalculationSourceRef`; обновить маппер `to-salary-report-rules.ts`.
- [ ] Тесты: `product-sold.entity.spec.ts`, `used-product-sold.entity.spec.ts`, тест маппера `to-salary-report-rules.ts`, regression `get-employee-salary-report.service.spec.ts`.

**Когда готово**: `GET /v1/shop/accounting/salary_report/employee/:id/:period` возвращает название товара и рабочую ссылку на документ отгрузки в `source` для правил `ProductSold` и `UsedProductSold`; все существующие тесты проходят, новые тесты — зелёные.

### Фаза 4: Frontend — отображение названия товара и ссылки на документ (shop)
**Цель**: Пользователь видит название товара и переходит по ссылке на документ отгрузки МойСклад на странице зарплатного отчёта, для направления shop.
**Что затрагивает?** frontend
**Задачи:**
- [ ] Обновить компонент детализации источников начисления на `/salaries` для направления shop — использовать новое поле названия товара и ссылку на документ.
- [ ] Обновить типы source на фронтенде под новые поля (если типы разделены по направлению service/shop).
- [ ] Убедиться, что fallback на generic-лейбл сохраняется для правил без документа (`PayPerHour`, `TaskCompleted`).
- [ ] Ручная проверка в браузере: открыть `/salaries` для сотрудника магазина с начислениями по правилам "Вознаграждение за проданный товар" и "Вознаграждение закупщику Б/У техники", убедиться, что видно название товара и рабочая ссылка.
- [ ] Тесты: компонентный/снапшот-тест детализации источников для shop-направления, если применимо.

**Когда готово**: на `/salaries` в раскрытой детализации правил "Вознаграждение за проданный товар" и "Вознаграждение закупщику Б/У техники" отображается название товара и кликабельная ссылка на документ отгрузки МойСклад; остальные правила визуально не изменились.
