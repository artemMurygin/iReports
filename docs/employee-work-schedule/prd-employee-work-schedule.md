# PRD: График работы сотрудников

**Дата**: 2026-08-20
**Статус**: Draft

## Цель

Дать руководителю единое место, где видно, кто из сотрудников в какой день работает, сколько часов и в какой роли, и сделать этот график источником отработанных часов для зарплатного правила `PayPerHour` вместо сегодняшнего ручного ввода «сотрудник + период → часы» (`EmployeeHoursEntry`).

Дизайн: `design/sallary-first-iteration.pen`, узлы `Cko6w` (Календарь), `vO4tI` (Роли), `A5SbT` (Мобильный «Отдел сегодня»).

## Пользовательские сценарии

- Руководитель открывает «График работы» → видит таблицу «сотрудники × дни месяца» с часами за каждую смену, итогом часов за месяц по каждому сотруднику и числом людей в смене по каждому дню.
- Руководитель нажимает на ячейку дня → в поповере выбирает статус дня (Работает / Выходной / Отгул / Больничный / Отпуск) и, для рабочего дня, количество часов смены → ячейка и все итоги (часы сотрудника, люди в смене, общий фонд часов) пересчитываются.
- Руководитель ставит сотруднику статус «Отпуск» → в строке сотрудника растёт счётчик использованных дней отпуска, в поповере видно остаток дней отпуска на текущий год.
- Руководитель переключается на вкладку «Роли» → та же таблица, но в ячейке роль, в которой сотрудник работал в этот день (Инженер / Онлайн-менеджер / Офлайн-менеджер / Офис) → назначает роль на конкретный рабочий день.
- Руководитель переключает месяц → таблица показывает график выбранного месяца.
- Руководитель фильтрует таблицу по отделу → видит только сотрудников этого отдела.
- Сотрудник/руководитель открывает страницу с телефона → видит экран «Отдел сегодня»: ленту дней недели с числом людей, состав смены с ролями и часами, счётчики ролей на смене и список отсутствующих с причинами.
- Бухгалтер/руководитель открывает зарплатный отчёт сотрудника за период → строка правила «оплата по часам» посчитана по сумме часов рабочих смен этого сотрудника за период из графика.

## В скоупе

**Данные**
- Новая сущность «смена сотрудника»: пара (сотрудник, календарный день) → статус дня, часы смены, роль дня. Уникальность по паре (сотрудник, день).
- Статусы дня: `WORKING`, `DAY_OFF` (выходной), `TIME_OFF` (отгул), `SICK_LEAVE` (больничный), `VACATION` (отпуск).
- Часы смены — только у статуса `WORKING`, диапазон 2–16 с шагом 0,5.
- Роль дня — только у статуса `WORKING`, значение из `TargetRole`.
- Роль `OFFICE` («Офис») добавляется в `TargetRole` (`contracts`, `salary_role_types`, метки на фронте).

**API (общий модуль на компанию, без разделения service/shop)**
- Чтение графика за месяц с фильтром по отделу: строки сотрудников со сменами, итогом часов за месяц, использованными и всего доступными днями отпуска; агрегаты по дням (число людей в смене) и общий фонд часов.
- Создание/изменение записи дня (статус, часы, роль) и удаление записи (возврат дня в состояние «не заполнен»).
- Чтение состава смены на конкретную дату для мобильного экрана: кто на смене (с ролью и часами), кто не на смене с группировкой по причине отсутствия, счётчики ролей.
- Годовой лимит отпуска и остаток по сотруднику.

**Интеграция с зарплатой**
- `hoursWorked` в контексте расчёта (`build-service-calculation-context`, `build-shop-calculation-context`) считается как сумма часов смен со статусом `WORKING` за период вместо чтения `EmployeeHoursEntry`.
- Существующие данные `EmployeeHoursEntry` мигрируются в график, модель и её CRUD-эндпоинты (`POST/PATCH/DELETE/GET /v1/service/accounting/employee_hours`) удаляются.

**UI**
- Страница «График работы» в основной навигации с вкладками «Календарь» и «Роли».
- Таблица «сотрудники × дни месяца»: заголовок дня с числом и днём недели, выделение сегодняшнего дня и выходных, легенда обозначений, липкая колонка сотрудника.
- Итоговые колонки: часы за месяц, использованные дни отпуска из годового лимита.
- Итоговая строка «Человек в смене» по каждому дню и общий фонд часов за месяц.
- Поповер редактирования дня: дата, имя сотрудника, выбор статуса, слайдер часов (2–16, шаг 0,5), остаток дней отпуска.
- Вкладка «Роли»: та же таблица, в ячейке — роль; редактирование роли рабочего дня.
- Переключение месяца и фильтр по отделу.
- Мобильный экран «Отдел сегодня» по узлу `A5SbT`, включая переход с сотрудника на его график.

## Не в скоупе

- Вкладка «Дефолтные графики», шаблоны-паттерны (5/2, 2/2, 6/1) и кнопка «Проставить на 3 месяца» — заполнение графика в этой итерации только ручное, по ячейкам. Подпись паттерна под именем сотрудника в дизайне не реализуется: источника данных для неё нет.
- Заявки на отпуск/отгул и любой воркфлоу согласования — руководитель проставляет статусы напрямую.
- Учёт фактического прихода/ухода, табель, опоздания, переработки сверх часов смены.
- Импорт графика из внешних систем (Bitrix24, RemOnline, МойСклад) и экспорт.
- Права доступа и ограничение редактирования по ролям пользователя — эндпоинты без гарда, как остальной `accounting` сегодня.
- Уведомления об изменениях графика.
- Планирование графика по точкам/филиалам.

## Технические ограничения

- Сотрудник — `BitrixEmployee` (Bitrix24 — единственный источник истины о человеке), отдел — `BitrixDepartment`; список сотрудников и отделов берётся из `/v1/directory/*`.
- Роль дня и `SalaryRule.targetRole` используют один enum `TargetRole`: добавление `OFFICE` затрагивает `contracts/commands/salary-rule.ts`, `salary-rule-role-catalog.ts`, `ROLE_LABELS` и формы зарплатных правил; каталог `salary_role_types` при этом не обязан отдавать `OFFICE` как допустимую роль для существующих типов правил.
- Модуль общий на компанию: у сущности нет дискриминатора `direction`, при этом её читают контексты расчёта обоих направлений (`service` и `shop`).
- Замена источника часов меняет результат расчёта уже посчитанных открытых периодов: после миграции нужен сброс кэша расчёта (`AccountingCalculationCache`). Закрытые периоды защищены снапшотом и не пересчитываются.
- Часы за месяц — сумма `Float`; итоги в отчётах и в таблице должны совпадать до одного знака после запятой.
- Таблица на 13+ сотрудников × 31 день — одна выборка на месяц, без N+1 запросов на сотрудника или день; агрегаты считаются на бэкенде, а не в браузере.
- Годовой лимит отпуска (31 день в дизайне) — единый для всех сотрудников, хранится как константа/настройка, не поле сотрудника.
- Фронтенд — FSD: страница в `pages/`, работа с данными через TanStack Query, компоненты из нового UI Kit (`ERP/*` в дизайне).

## Критерии готовности

- [ ] `GET` графика за месяц возвращает по каждому сотруднику отдела 28–31 ячейку с статусом/часами/ролью, итог часов и использованные дни отпуска; для месяца без данных — пустые ячейки без ошибки.
- [ ] Создание записи дня для пары (сотрудник, дата), уже имеющей запись, изменяет её, а не создаёт вторую (уникальность соблюдена).
- [ ] Часы вне диапазона 2–16 или не кратные 0,5 отклоняются с `400`.
- [ ] Часы или роль, переданные со статусом, отличным от `WORKING`, отклоняются с `400`.
- [ ] `GET` состава смены на дату возвращает список на смене с ролью и часами, список отсутствующих, сгруппированный по причине, и счётчики по ролям; суммы «на смене» + «не на смене» равны числу сотрудников отдела.
- [ ] `OFFICE` принимается как `targetRole` в контрактах и отображается как «Офис» на фронте; существующие зарплатные правила и их тесты не сломаны.
- [ ] `PayPerHour` в отчёте сотрудника за период даёт `quantity`, равное сумме часов смен `WORKING` за этот период; период без смен даёт `0`, а не ошибку.
- [ ] Миграция переносит каждую запись `EmployeeHoursEntry` в график так, что зарплатный отчёт за мигрированный период даёт то же значение `quantity` у `PayPerHour`, что и до миграции.
- [ ] Модель `EmployeeHoursEntry`, её эндпоинты, порты, хендлеры и репозиторий удалены; сборка бэкенда и `ENDPOINTS.md` не содержат упоминаний `employee_hours`.
- [ ] Страница «График работы» доступна из навигации, вкладки «Календарь» и «Роли» переключаются без потери выбранного месяца и отдела.
- [ ] Клик по ячейке открывает поповер, сохранение изменяет ячейку и пересчитывает итог часов сотрудника, счётчик «Человек в смене» за день и общий фонд часов.
- [ ] Проставление статуса «Отпуск» увеличивает счётчик использованных дней отпуска сотрудника и уменьшает остаток в поповере.
- [ ] Мобильный экран «Отдел сегодня» показывает состав смены, счётчики ролей и отсутствующих по причинам; переключение дня недели меняет состав.
- [ ] Тесты бэкенда (unit + e2e новых эндпоинтов) и `npm run build` фронтенда проходят.
