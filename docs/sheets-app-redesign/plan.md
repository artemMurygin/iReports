# План реализации: редизайн sheets-app (макет Pencil gMFNd)

Change: `sheets-app-redesign`. Все ID требований ниже скоупятся этим именем (`sheets-app-redesign.FR1` и т.д.), см. `.claude/rules/traceability.md`.

Источник макета: `design/sallary-first-iteration.pen`, фрейм `gMFNd`, пять экранов шириной 300px: `YWoAp` (Мой склад, старт), `iZi9s` (Мой склад, результаты), `Cqdmp` (Ремонлайн), `L6oNMo` (Ремонлайн, результат и подсказка), `MIA9P` (Ремонлайн, прогресс).

## 1. Цель и scope

### Покрытие экранов макета фазами

| Экран | Что показывает | Фазы |
|---|---|---|
| `YWoAp` | МС, старт: Dropzone, «Требования», 3 карточки idle | 3 (виджеты), 4 |
| `iZi9s` | МС: File Card, success `11:25 · 253 позиции`, error `ошибка 429`, баннер ошибки | 3, 4, 7 (код 429; число «253 позиции» не воспроизводится, у МС только время, Q10) |
| `Cqdmp` | РО: 3 карточки idle, секция «Записать категорию в ячейку» с 4 Select | 5 |
| `L6oNMo` | РО: тултип, success-карточка, блок итогов | 3, 5 |
| `MIA9P` | РО: модалка прогресса поверх экрана (футер «Отчёт о последней операции» в макете игнорируется, Q2; 43 % и ETA для блокирующего вызова не воспроизводятся, Q4) | 6 |

Состояния, которых в макете нет, но код их уже имеет: warning-баннер («Нет строк со значением "Создать"», «Выберите файл»), загрузка и ошибка загрузки дерева категорий, прогресс загрузки прайса в МС (SSE), running внутри карточки, пустой итог. См. Q12.

**Цель.** Перевести сайдбар Google Sheets (`sheets-app/`) на новый визуальный язык: светлая тема с чёрным и зелёным брендом, карточки функций с индивидуальным статусом, модалка прогресса, блок итогов, тултипы, каскадный выбор категории.

**В scope**
- Токены, шрифты, `shared/ui`, новые виджеты, переверстка обеих панелей.
- Модель статусов по функциям (idle / success / error) и хранение «последнего запуска».
- Модалка прогресса (кольцо, полоса; процент, ETA и отмена только там, где данные уже есть, для блокирующих вызовов неопределённая полоса).
- Расширение `GasApi` и Apps Script там, где дизайн требует данных, которых нет.
- Переписывание тестов UI на устойчивые селекторы.

**Вне scope (non-goals)**
- NG1. Тёмная тема. Тёмные токены в `.pen` относятся к неиспользуемому шаблону.
- NG2. Роутер, TanStack Query, слои `pages` и `kernel`. Это один экран-сайдбар.
- NG3. Изменения бэкенда `backend/`, пока не подтверждена необходимость (см. Q3).
- NG4. Домен `opt`, новые бизнес-функции. Набор функций остаётся прежним.
- NG5. Автоматический деплой через `clasp push`. Деплой остаётся ручным.
- NG6. Футер «Отчёт о последней операции» (Q2).
- NG7. Клиентская разбивка `uploadPricesToRO` на партии, ETA, процент и отмена для блокирующих вызовов (Q4). Обновление существующих услуг в `createServiceInRoapp` (Q11).

## 2. Требования

### Цели
- G1. Сайдбар визуально соответствует макету gMFNd (пять экранов).
- G2. Логика синхронизации и контракт с GAS не регрессируют.
- G3. UI-тесты становятся регрессионной сеткой на `role` и `testid`, а не на эмодзи и точные строки.

### Функциональные требования
- FR1. Каркас: шапка (Mark, название «iRepair · Синхронизация», справка: иконка-кнопка `ERP/Atom/Icon Button`, иконка info, ref `qVdml`, правый край Header, `aria-label="Справка"`; по клику открывает тултип (popover) с кратким описанием приложения: что делает «iRepair · Синхронизация» (загрузка прайсов в МойСклад и Ремонлайн, получение цен, начисления мастеров, запись категории в ячейку); текст захардкожен в `AppHeader`, закрытие по клику вне, `Esc` и повторному клику, Q14), вкладки «Мой склад» и «Ремонлайн», разделитель, Body. Футера нет (Q2).
- FR2. Мой склад, источник: Dropzone (drag-and-drop и выбор `.xlsx`), блок «Требования», после выбора File Card (иконка, имя файла, кнопка Remove), возвращающий Dropzone. Блок «Требования» (иконка list-checks) показывается только вместе с Dropzone, в состоянии File Card его нет; текст захардкожен в компоненте или конфиге МС (`moySkladFunctions.ts`), без дополнительной конфигурации (Q8). Под File Card добавляется кнопка «Загрузить прайс» (чёрная, block), запускающая существующую цепочку `processFile` и SSE (Q13); в макете её нет, добавляется решением плана.
- FR3. Функции сгруппированы по направлению («Отправить в…», «Получить из…») с Group Label. Каждая функция показана карточкой `FuncCard`: плитка (brand = стрелка вверх, copper = гаечный ключ только у «Создать услуги», info = стрелка вниз), название, описание, Info Dot, футер. Карточек пять-шесть: МС три («Обновить РЦ в МойСклад», «Обновить акционную РЦ», «Получить цены из МойСклад»), РО три («Загрузить цены в RO», «Создать услуги в Ремонлайн», «Обновить начисления мастеров»). Группы РО: «Отправить в Ремонлайн» (2 карточки), «Получить из Ремонлайн» (1).
- FR4. Статусы `FuncCard`: idle («ещё не запускалось», «Запустить»), success («ЧЧ:ММ» и, если число известно, « · N»; у функций МойСклад только время без числа, Q10; «Повторить»), error («ЧЧ:ММ · ошибка NNN», «Повторить» с красной обводкой). Статус каждой функции независим. Остальные состояния: disabled с `opacity-50`, фокус-кольцо `--ring`, прочее по коду (Q12).
- FR5. Тултип Info Dot: заголовок, тело, мета (только «пишет в …», без оценки времени и без иконки часов, Q17). Тексты по функциям (существующий длинный текст «Создать услуги» про обязательные поля сокращается, полный список остаётся в README), хранятся в `*Functions.ts`:

  | Обновить акционную РЦ | Обновить акционную РЦ | Записывает акционные цены из листа в МойСклад. Обычные розничные цены не меняются. | пишет в МойСклад |

- FR6. Блок ошибки `Status` (err): сообщение, деталь, кнопка закрытия. Показывается при ошибке функции, содержит HTTP-код и текст, когда они известны. Заголовок «МойСклад ответил NNN», деталь по таблице ниже (если код не из таблицы, деталь берётся из тела ответа или общий текст «Неожиданный ответ сервиса»). Закрытие баннера не сбрасывает ошибку в карточке. Нужен также вариант warning (Q12).

  | Код | Заголовок | Деталь |

  | 400 | МойСклад ответил 400 | Некорректный запрос · проверьте данные в листе |

  | 5xx | МойСклад ответил 5NN | Сервис МойСклад временно недоступен · повторите позже |
  | сетевая | Нет связи с МойСклад | Проверьте подключение и повторите |
- FR7. Блок итогов `Result` (заголовок, Badge «Готово», `StatRow`: Всего, Валидных, Создано, Обновлено, Ошибок). В макете один, под карточкой «Создать услуги» с заголовком «Итог создания услуг», но значения (253 / 253 / 0 / 253 / 0) соответствуют `UploadPricesToRoResult.count`. Решение (Q15): блок привязан к функции и показывается под её карточкой с собственным заголовком: «Итог загрузки цен» для RO (пять строк по макету, строка «Обновлено» берётся из результата `uploadPricesToRO`), «Итог создания услуг» для создания (строки Всего, Создано, Ошибок по `total, created, errors`; «Валидных» и «Обновлено» скрыты, обновления существующих услуг нет, Q11). Badge: «Готово» (success), «С ошибками» (errors > 0), прочее по умолчанию (Q12).
- FR8. Секция «Утилиты» с заголовком «Записать категорию в ячейку» (вкладка Ремонлайн, ниже групп функций), всегда раскрыта: кнопки-переключателя «Добавить новую услугу» в макете нет, значит дерево категорий грузится при открытии вкладки (с состоянием загрузки и ошибки, Q12). Внутри: строка пути (иконка git-branch, разделитель ` / ` только для отображения), каскадные `Select` (уровней столько, сколько есть в дереве; в макете три выбранных и четвёртый placeholder «Выберите услугу» с прочерком), серые моно-индексы макета («01», «02») не данные и не выводятся: в `Select` показываются только названия категорий (Q16), кнопка «Записать категорию» (чёрная, иконка corner-down-left; активна только при выбранном последнем уровне). В записываемой в ячейку строке разделитель остаётся ` > `, как в `categoryTree.ts` и `validation.ts`.
- FR9. Модалка прогресса: Ring, заголовок (свой у каждой функции, в макете «Выгружаем цены в RO»), полоса, процент, ETA («осталось ~N сек»), подсказка «Не закрывайте таблицу», кнопка «Отмена», Scrim. Подзаголовка нет (Q1). Процент, ETA и «Отмена» показываются только там, где данные уже есть: клиентские циклы и SSE импорта МС. Для блокирующих вызовов (`uploadPricesToRO`, вебхуки МС) неопределённая полоса, без процента и ETA, кнопка «Отмена» скрыта (Q4); цифры 43 % и «~25 сек» из макета `MIA9P` не воспроизводятся. Состояния без макета: Q12.
- FR10. Отменено (Q2): футер «Отчёт о последней операции» не делаем. ID не переиспользуется.
- FR11. Хранение статуса и времени последнего запуска по каждой функции между открытиями сайдбара (`PropertiesService.getDocumentProperties()`).
- FR12. Разбор ошибок МойСклад: HTTP-код и тело ответа вебхуков n8n доходят до UI. Сейчас вебхуки вызываются без `muteHttpExceptions`, и `UrlFetchApp` бросает исключение с текстом вида «Request failed for ... returned code 429», поэтому в Фазе 4 код извлекается regexp'ом из текста, а в Фазе 7 приходит структурно.
- FR13. Отмена операции: для клиентских циклов (создание услуг, начисления) флагом между итерациями, для SSE импорта МС закрытием потока; для блокирующих вызовов кнопка скрыта (Q4).

### UX
- UX1. Ширина 300px, горизонтальный скролл отсутствует, Body padding 14.
- UX2. Состояния Dropzone: default, hover и drag-over, после выбора (File Card), ошибка формата.
- UX3. Select в фокусе: толстая тёмная обводка. Placeholder «Выберите услугу» с прочерком; индексов уровней нет (Q16).
- UX4. Длинный meta-текст в футере карточки обрезается через ellipsis и не вытесняет кнопку.
- UX5. Модалка закрывает взаимодействие (Scrim), фокус удерживается внутри, `Esc` равен «Отмена» там, где отмена доступна.
- UX6. Все иконки-кнопки имеют `aria-label`, статусы в `aria-live="polite"`.

### Нефункциональные
- NFR-P1. Итоговый `dist/index.html` (singlefile) не превышает лимит `HtmlService` и не растёт более чем на 400 КБ из-за шрифтов.
- NFR-A1. Контраст основного текста не ниже 4.5:1. `#C4C4C4` на белом допустим для eyebrow и мета (Q6, решено). Навигация с клавиатуры по всем интерактивным элементам.
- NFR-R1. Вёрстка корректна при ширине сайдбара 300px, высота не фиксирована.
- NFR-C1. Шрифты и иконки только инлайном или base64 (ограничение singlefile и `HtmlService`). `vite.config.ts` уже задаёт `assetsInlineLimit: 100000000`. Пакетов `@fontsource/*` в `sheets-app/package.json` нет, их нужно добавить в devDependencies (Фаза 1). Иконки из `lucide-react` (уже в зависимостях), точные имена проверить по установленной версии.

### Метрики
- M1. Ноль ссылок на удалённые токены `brand-green*`, `brand-blue`, `brand-orange`, `brand-red`.
- M2. Все тесты зелёные, покрытие новых виджетов минимум render-smoke.
- M3. Пиксельная сверка пяти экранов с PNG из макета в Playwright-скриншотах (допуск на шрифт-рендеринг) пройдена вручную дизайнером.

Правила импортов: `shared` не знает о `features`; `features/moySklad` и `features/remonline` не импортируют друг друга, общее живёт в `features/operations` или `shared`. Тексты функций, тултипы и описания держим в конфигах `*Functions.ts`, а не в JSX.

Модель состояния: `GlassLoader` и единый `status` в `App.tsx` заменяются на `Record<FunctionId, OperationState>` (`idle | running | success | error` плюс `finishedAt`, `summary`, `error`). Один активный запуск одновременно (кнопки неактивных функций блокируются под Scrim).

## 8. Риски

1. **Размер singlefile.** Шрифты в base64 раздувают `upload.html`. Митигация: subset, минимум весов, замер в Фазе 1.
2. **Прогресс без данных.** Для блокирующих вызовов честного процента нет. Митигация: неопределённая полоса (Q4), клиентские партии не делаем; не имитировать фальшивые проценты.

5. **Хрупкие тесты.** Фаза 0 снижает риск, без неё Фазы 4-5 ломают сетку.
6. **Дрейф дизайна.** Макет содержит элементы, которые не реализуются (футер-отчёт, процент и ETA для блокирующих вызовов) и неполные состояния. Митигация: решения зафиксированы в разд. 9, состояния без макета принимаются по умолчанию (Q12).
7. **Ручной деплой.** Нет автоматической проверки в реальной таблице. Митигация: чек-лист ниже, обязателен в PR фаз 4-7.
8. **Лимиты хранения `PropertiesService`** (9 КБ на значение, 500 КБ всего): хранить только сводки и до N ошибок, не полные отчёты.
