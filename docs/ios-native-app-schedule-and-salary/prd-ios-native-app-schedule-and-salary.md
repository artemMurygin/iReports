# PRD: Нативное iOS-приложение — график работы и зарплата

**Дата**: 2026-09-10
**Статус**: Draft

## Цель

Дать сотрудникам и руководителям отделов доступ к своему графику работы, графику отдела и отчётам по зарплате с телефона, в нативном iOS-приложении с дизайном Liquid Glass, без необходимости открывать веб-версию iReports в браузере.

## Пользовательские сценарии

- Сотрудник открывает приложение впервые -> авторизуется через Bitrix24 (тот же OAuth-флоу, что и в браузере) -> попадает на свой график/зарплату без повторного ввода логина при следующих запусках.
- Сотрудник открывает вкладку «Мой график» -> видит свои смены на неделю/месяц (рабочий день, выходной, отгул, больничный, отпуск).
- Сотрудник нажимает на день в своём графике -> отмечает отсутствие (больничный/отгул) или отправляет запрос на смену -> видит обновлённый статус дня после подтверждения.
- Руководитель/сотрудник открывает вкладку «График отдела» -> видит смены всех сотрудников отдела на выбранный день/неделю, как в веб-версии «Отдел сегодня».
- Сотрудник открывает вкладку «Моя зарплата» -> видит отчёт за выбранный период: начисления по правилам, итоговую сумму, разбивку по направлениям (Сервис/Розница), как в веб-отчёте `/salaries/employee/:employeeId`.
- Руководитель открывает вкладку «Зарплата отдела» -> видит список сотрудников отдела с их итоговыми суммами за период, как в веб-отчёте `/salaries`.
- Сотрудник, у которого сессия истекла или недействительна -> при открытии приложения видит экран логина Bitrix24, а не пустой/сломанный экран.

## В скоупе

- Экран авторизации через Bitrix24 OAuth (authorization code flow), с возвратом в приложение через deep link (universal link или custom URL scheme) — по аналогии с уже описанным в проекте сценарием `openspec/specs/auth/spec.md` («OAuth-аутентификация в iOS-приложении»).
- Хранение и переиспользование сессии между запусками приложения (пользователь не логинится заново при каждом открытии, пока сессия валидна).
- Экран/вкладка «Мой график работы»: собственные смены сотрудника за период (неделя/месяц), статусы (рабочий день, выходной, отгул, больничный, отпуск) — по данным контракта `work-schedule.ts`.
- Экран/вкладка «График отдела»: смены сотрудников выбранного отдела за день/неделю — по аналогии с веб-экраном «Отдел сегодня» (`/work-schedule/today`).
- Возможность в «Моём графике» отметить своё отсутствие (больничный/отгул) и отправить запрос на смену дня — действие, а не только просмотр.
- Экран/вкладка «Моя зарплата»: отчёт по зарплате текущего сотрудника за выбранный период, с разбивкой по направлениям и правилам начисления — эквивалент веб-отчёта `/salaries/employee/:employeeId`.
- Экран/вкладка «Зарплата отдела»: список сотрудников отдела с итоговыми суммами за период — эквивалент веб-отчёта `/salaries`.
- Выбор периода (месяц) и отдела/направления для отчётов, где это применимо на вебе.
- Визуальный дизайн, идентичный текущему мобильному фронтенду iReports (цвета, типографика, компоновка), с UI-компонентами в стиле Liquid Glass (SwiftUI-адаптация для React Native).
- Экран выхода из аккаунта (logout).
- Приложение только для iOS, минимальная поддерживаемая версия — iOS 26 (обязательное условие для нативного отображения Liquid Glass).

## Не в скоупе

- Android-версия приложения.
- Любые другие разделы iReports, кроме графика работы и зарплаты (аналитика сделок, воронка продаж, склад, задачи и т.д.).
- Редактирование графика отдела (руководитель не может через приложение менять смены других сотрудников — только просматривать).
- Редактирование/утверждение начислений зарплаты, правил зарплаты, документов начисления.
- Встроенный (iframe) режим авторизации Bitrix24 — используется только standalone OAuth-редирект.
- Push-уведомления, офлайн-режим, синхронизация в фоне.
- Поддержка iOS-версий ниже 26 (fallback-дизайн без Liquid Glass не делаем).
- Публикация в App Store в рамках этой итерации (только сборка и внутреннее распространение).

## Технические ограничения

- Liquid Glass как визуальный язык доступен нативно только с iOS 26 — на более старых устройствах компоненты не будут выглядеть корректно, поэтому минимальная версия ОС жёстко зафиксирована.
- OAuth-редирект в standalone-приложении требует настроенного deep link (universal link или custom URL scheme) в конфигурации Bitrix24-приложения и обработки возврата в RN/Expo (аналог `ASWebAuthenticationSession`).
- Сессия на вебе для standalone-режима передаётся HttpOnly/Secure/SameSite=None cookie — для мобильного клиента (не браузер) нужно определить, как сессия будет доставляться и храниться на устройстве, так как cookie-хранилище браузера недоступно нативному приложению.
- Возможность действий с графиком (отметить отсутствие, запросить смену) требует наличия соответствующих command-эндпоинтов на бэкенде — на данный момент в `work-schedule.ts` описаны схемы для чтения графика; наличие и форма command-эндпоинтов на запись должны быть проверены/согласованы отдельно.
- Данные и контракты (`ireports-contracts`) переиспользуются как есть; новых полей/эндпоинтов сверх уже существующих в `work-schedule.ts` и `salary-rule.ts` эта итерация не предполагает, за исключением того, что необходимо для действий «отметить отсутствие»/«запросить смену».
- Пакет мобильного приложения не входит в npm workspaces монорепозитория (по аналогии с `frontend`), устанавливается и собирается независимо, потребляя `ireports-contracts` как обычную зависимость.

## Критерии готовности

- [ ] Сотрудник может авторизоваться через Bitrix24 OAuth и вернуться в приложение авторизованным без ручного копирования кода/токена.
- [ ] После перезапуска приложения авторизованный сотрудник не видит повторно экран логина, пока сессия действительна.
- [ ] На экране «Мой график» отображаются смены и статусы (рабочий день/выходной/отгул/больничный/отпуск) текущего сотрудника за выбранный период, совпадающие с данными на вебе для того же периода.
- [ ] На экране «График отдела» отображаются смены сотрудников выбранного отдела за выбранный день/неделю, совпадающие с данными на вебе.
- [ ] Сотрудник может отметить отсутствие (больничный/отгул) в своём графике, и статус дня обновляется после подтверждения.
- [ ] Сотрудник может отправить запрос на смену дня в своём графике и увидеть отражённый статус запроса.
- [ ] На экране «Моя зарплата» отображается сумма начислений и разбивка по направлениям/правилам за выбранный период, совпадающая с веб-отчётом `/salaries/employee/:employeeId` для того же сотрудника и периода.
- [ ] На экране «Зарплата отдела» отображается список сотрудников отдела с итоговыми суммами за выбранный период, совпадающий с веб-отчётом `/salaries` для того же отдела и периода.
- [ ] Сотрудник может выйти из аккаунта, после чего попадает на экран логина.
- [ ] Внешний вид экранов (цвета, типографика, компоновка) визуально соответствует текущему мобильному фронтенду iReports.
- [ ] Ключевые интерактивные элементы (карточки, панели, табы) используют Liquid Glass компоненты, а не стандартные iOS-элементы.
- [ ] Приложение запускается и корректно отображает Liquid Glass-интерфейс на устройстве/симуляторе с iOS 26.
