# Plan: Навигация по зарплате «сначала отдел»

**PRD** docs/salary-department-first-navigation/prd-salary-department-first-navigation.md
**Дата** 2026-08-25

## Фазы реализации

### Фаза 1: Убрать переключатель режима и Select сотрудника

**Цель** `/salaries` больше не даёт переключиться в режим «Сотрудник» вручную и не показывает Select выбора сотрудника — единственный вход в отчёт сотрудника остаётся через клик по строке в отделе или прямую ссылку.

**Что затрагивает?** frontend

**Задачи:**
- [ ] Убрать `SegmentedControl` режима «Сотрудник» / «Отдел» (`SCOPE_OPTIONS`) из `SalaryReportFiltersV2`.
- [ ] Убрать ветку `Select` выбора сотрудника (`scope === 'employee'`) из `SalaryReportFiltersV2`; для отдела оставить Select отдела + переключатель направления «Все/Сервис/Магазин» без изменений.
- [ ] Для режима «Сотрудник» филтр-роу рендерит только `PeriodPicker` (без Select'ов и без переключателя направления).
- [ ] Пройтись по `useSalaryReportPage`/`SalaryReportV2Page`: убрать из паблик-API страницы то, что было нужно только ручному переключателю (`setScope`, если он использовался лишь SegmentedControl'ом), не трогая логику, которая выводит `scope` из URL (`/salaries` vs `/salaries/employee/:id`).
- [ ] `npm run lint` и `npm run build` во `frontend/` проходят.

**Когда готово** На `/salaries` не отображается переключатель «Сотрудник»/«Отдел»; Select отдела и переключатель направления работают как раньше; клик по сотруднику в отделе открывает `/salaries/employee/:id`, где нет ни переключателя режима, ни Select'а сотрудника — проверено вручную в браузере (dev-сервер, оба сценария) плюс проходят lint/build.

### Фаза 2: Навигация назад к отделу со страницы сотрудника

**Цель** Со страницы отчёта сотрудника, куда после Фазы 1 не осталось UI-пути переключиться на другого сотрудника, есть явный путь вернуться к отчёту отдела.

**Что затрагивает?** frontend

**Задачи:**
- [ ] Добавить на `/salaries/employee/:id` ссылку/элемент навигации назад к отчёту отдела (например, в хедере страницы рядом с именем сотрудника).
- [ ] Проверить прямой заход на `/salaries/employee/:id` по ссылке/обновлению страницы (без предварительного захода через отдел) — отчёт сотрудника открывается без ошибок, ссылка «назад» ведёт на `/salaries`.
- [ ] Ручное тестирование в браузере обоих сценариев: переход из строки сотрудника в отделе → «назад» возвращает в отдел; прямой заход по ссылке на сотрудника → «назад» тоже работает.
- [ ] `npm run lint` и `npm run build` во `frontend/` проходят.

**Когда готово** На странице отчёта сотрудника есть рабочая ссылка назад к отчёту отдела; прямой заход по `/salaries/employee/:id` и переход по клику из отдела оба проверены вручную и не ломают навигацию; lint/build проходят.
