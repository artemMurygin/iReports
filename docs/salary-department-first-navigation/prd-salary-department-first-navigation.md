# PRD: Навигация по зарплате «сначала отдел»

**Дата**: 2026-08-25
**Статус**: Draft

## Цель

Убрать ручное переключение между режимами «Сотрудник» / «Отдел» на странице `/salaries`: точка входа в отчёт по зарплате — всегда отдел, а к отчёту конкретного сотрудника переходят кликом по его строке. Это готовит страницу к будущему личному кабинету, который будет вести сотрудника сразу на его собственный отчёт по прямой ссылке, без выбора себя из общего списка.

Дизайн: `design/sallary-first-iteration.pen`, узлы `wVa5g` («Зарплата отдела REFACTORING») и вложенный `SozIO`, панель фильтров `AqQmX`.

## Пользовательские сценарии

- Пользователь открывает `/salaries` → сразу видит отчёт по отделу (по умолчанию — «Розница»), без предварительного выбора режима «Сотрудник»/«Отдел».
- Пользователь выбирает другой отдел в Select'е отдела → видит отчёт выбранного отдела; переключатель направления «Все / Сервис / Магазин» продолжает работать как сейчас.
- Пользователь кликает по строке сотрудника в отчёте отдела → переходит на отчёт этого сотрудника (`/salaries/employee/:id`).
- Пользователь на странице отчёта сотрудника не видит ни переключателя «Сотрудник/Отдел», ни выпадающего списка для выбора другого сотрудника — единственный способ увидеть другого сотрудника — вернуться в отдел и кликнуть по другой строке.
- Пользователь на странице отчёта сотрудника переходит назад к отчёту отдела (по ссылке/хлебной крошке), из которого он пришёл.
- Пользователь открывает `/salaries/employee/:id` напрямую по ссылке (без захода через отдел) → видит отчёт этого сотрудника сразу, как и раньше.

## В скоупе

- Удаление переключателя режима «Сотрудник» / «Отдел» (`SegmentedControl` в `SalaryReportFiltersV2`) со страницы `/salaries` и `/salaries/employee/:id`.
- Удаление выпадающего списка выбора сотрудника (`Select` из `SalaryReportFiltersV2`, ветка `scope === 'employee'`) — на странице отчёта сотрудника такого поля быть не должно.
- `/salaries` без параметра всегда рендерит отчёт отдела; текущая логика дефолтного отдела «Розница» и Select выбора отдела сохраняются без изменений.
- Переключатель направления «Все / Сервис / Магазин» на отчёте отдела сохраняется без изменений.
- На странице отчёта сотрудника (`/salaries/employee/:id`) добавляется явная навигация назад к отчёту отдела (ссылка/хлебная крошка), поскольку выбора другого сотрудника через UI больше не остаётся — пользователю, перешедшему на страницу сотрудника, нужен явный путь обратно в список.
- Клик по строке сотрудника в отчёте отдела остаётся единственным способом перейти к отчёту конкретного сотрудника из UI отдела (переход уже реализован, `DepartmentEmployeeGroupV2`, и остаётся рабочим).
- Прямой переход по URL `/salaries/employee/:id` (без захода через отдел) продолжает открывать отчёт конкретного сотрудника — это тот же механизм, на который в дальнейшем будет ссылаться личный кабинет.

## Не в скоупе

- Личный кабинет и его ссылка на отчёт сотрудника — только контекст, почему убирается Select на странице сотрудника; сам личный кабинет реализуется отдельной задачей.
- Список отделов / переход между отделами без Select'а — Select отдела остаётся как есть, его переделка не входит в эту итерацию.
- Изменение переключателя направления «Все / Сервис / Магазин» — остаётся как есть.
- Права доступа и ограничение видимости отчёта сотрудника (кто может открыть чужой отчёт по прямой ссылке) — не меняются в этой итерации.
- Визуальный редизайн карточек отчёта отдела/сотрудника сверх уже внесённых изменений — здесь речь только о навигации, не о вёрстке содержимого отчётов.

## Технические ограничения

- Обе точки входа (`/salaries` и `/salaries/employee/:id`) рендерят один и тот же компонент страницы (`SalaryReportV2Page`) на одной глубине роутера — переход между ними не должен вызывать полный ремонт компонента и потерю уже загруженных данных периода/направления.
- Фронтенд — FSD: изменения ограничены `pages/SalaryReportV2` (`ui/SalaryReportFiltersV2.tsx`, `model/useSalaryReportPage.ts` и связанные типы), без выноса в `features`.

## Критерии готовности

- [ ] На `/salaries` не отображается переключатель «Сотрудник» / «Отдел».
- [ ] На `/salaries` отображается отчёт по отделу (дефолт — «Розница») и Select выбора отдела, как сейчас.
- [ ] Переключение отдела в Select'е обновляет отчёт; переключатель направления «Все / Сервис / Магазин» работает без изменений.
- [ ] Клик по строке сотрудника в отчёте отдела открывает `/salaries/employee/:id` этого сотрудника.
- [ ] На `/salaries/employee/:id` не отображается ни переключатель «Сотрудник» / «Отдел», ни выпадающий список выбора сотрудника.
- [ ] На `/salaries/employee/:id` есть ссылка/элемент навигации назад к отчёту отдела.
- [ ] Прямой заход по `/salaries/employee/:id` (обновление страницы, переход по внешней ссылке) открывает отчёт этого сотрудника без ошибок и без необходимости что-либо выбирать.
- [ ] `npm run build` и `npm run lint` фронтенда проходят.
