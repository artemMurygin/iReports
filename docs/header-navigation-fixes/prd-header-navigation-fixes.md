# PRD: Исправление подсветки и порядка пунктов навигации в хедере

**Дата**: 2026-09-03
**Статус**: Draft

## Цель

Хедер приложения нестабильно подсвечивает активные пункты верхнего и нижнего меню при переходах между страницами раздела «Зарплата» (и потенциально других разделов), а порядок пунктов верхнего меню не соответствует ожидаемой пользователем IA. Нужно починить логику определения «что сейчас активно», привести порядок пунктов к целевому и убрать архитектурные проблемы в коде навигации/хедера, из-за которых баги такого рода тихо возникают и будут возникать снова.

## Пользовательские сценарии

- Пользователь открывает `/salary-accruals`, `/salary-accruals/:id` или `/balance`, `/balance/employee/:id` → верхний пункт меню «Зарплата» остаётся подсвеченным как активный (сейчас гаснет, потому что верхний пункт матчится только на `/salaries*`).
- Пользователь переходит на `/sales-plan` из раздела «Продажи» → верхний пункт «Продажи» остаётся подсвеченным (сейчас гаснет сразу же, т.к. верхний пункт матчится только на точный `/`).
- Пользователь открывает `/salaries/rules` → в нижнем меню (Subnav) подсвечен ровно один пункт «Правила начисления», а не одновременно «Отчёт по зарплате» и «Правила начисления».
- Пользователь смотрит на верхнее меню (десктоп и мобильная шторка) → видит пункты в порядке: Продажи, Зарплата, График работы, Аналитика, Настройки.
- Разработчик открывает `navigation.tsx`/`Header.tsx`/`HeaderDesktop.tsx`/`Subnav.tsx`/`NavDrawer.tsx` → находит один переиспользуемый механизм определения активного пункта/раздела и один явный источник порядка пунктов, без противоречащих комментариев и дублирующихся типов.

## В скоупе

- Исправление определения активного верхнего пункта меню для разделов с несколькими дочерними страницами, чьи пути не образуют общий префикс (в первую очередь «Зарплата»: `/salaries*`, `/salary-accruals*`, `/balance*`; тот же класс бага у «Продажи»: `/` vs `/sales-plan`).
- Исправление логики Subnav так, чтобы на любом пути раздела «Зарплата» подсвечивался ровно один таб, а не несколько одновременно (конфликт `/salaries` и `/salaries/rules`).
- Изменение порядка пунктов верхнего меню на десктопе и в мобильной шторке на: Продажи, Зарплата, График работы, Аналитика, Настройки.
- Устранение дублирования логики «что активно» между `HeaderDesktop.tsx`, `Subnav.tsx`, `NavDrawer.tsx` (три независимые копии `NavLink.isActive`) и уже существующим корректным алгоритмом `matchPath`+«самый специфичный путь» в `app/Header.tsx` — они должны использовать один и тот же механизм.
- Устранение дублирующихся типов пункта меню (`HeaderNavItem`, `SubnavTab`, `NavDrawerItem`, `NavLeaf`), описывающих одну и ту же форму данных в четырёх местах.
- Явное, декларативное задание состава и порядка пунктов верхнего меню в одном месте (сейчас порядок — побочный эффект позиции объекта внутри литерала `SECTIONS` плюс отдельно приклеенный `STANDALONE_ITEM`).
- Приведение комментариев в `navigation.tsx` и `HeaderDesktop.tsx` про декоративный chevron в соответствие с фактическим поведением (сейчас два комментария и код рассказывают три разные версии одной и той же фичи).

## Не в скоупе

- Визуальный редизайн хедера (цвета, отступы, иконки, токены) — уже реализован в `shared/ui-kit`, не трогаем.
- Контент выпадающих меню профиля/уведомлений — отдельная задача, уже отмеченная как «осознанно не сделано».
- Добавление новых разделов/страниц навигации.
- Изменение URL-путей (`path`) существующих страниц — меняем только порядок пунктов меню и логику подсветки, не структуру роутинга.
- Мобильный App Bar и Scrim как отдельная фича — наследуют тот же порядок и логику активности, отдельных мобильных требований нет.

## Технические ограничения

- Стек: React Router v7.18 (`NavLink`, `matchPath`), правки должны оставаться совместимыми с текущей версией.
- В `app/Header.tsx` уже есть корректный алгоритм выбора «самого специфичного» активного пути (`matchPath` по всем листьям + `reduce` по длине `to`) — он должен стать переиспользуемым источником истины, а не быть заново изобретён в другом месте.
- Разделы с одной дочерней страницей («Аналитика», «Настройки», «График работы») сейчас работают корректно «по построению» — рефакторинг не должен их сломать.
- FSD-границы должны сохраниться: `shared/ui-kit/organisms/Header/*` — презентационный слой без бизнес-логики определения активного раздела; вычисление активности остаётся ответственностью `app`-слоя.
- Корректность подсветки на данный момент вручную зависит от согласованности флага `end` на каждом пункте в `navigation.tsx` (расставлен для `/` , но не для `/salaries`) — итоговое решение не должно требовать от разработчика помнить и вручную синхронизировать этот флаг между разделами.

## Критерии готовности

- [ ] На каждом пути раздела «Зарплата» (`/salaries`, `/salaries/rules`, `/salaries/rules/new`, `/salaries/rules/:direction/:id`, `/salaries/employee/:id`, `/salary-accruals`, `/salary-accruals/:id`, `/balance`, `/balance/employee/:id`) верхний пункт меню «Зарплата» подсвечен как активный.
- [ ] На `/salaries/rules` в Subnav подсвечен ровно один таб — «Правила начисления».
- [ ] При переходе между дочерними страницами раздела «Продажи» (`/` ↔ `/sales-plan`) верхний пункт «Продажи» не гаснет.
- [ ] Порядок пунктов верхнего меню на десктопе и в мобильной шторке: Продажи, Зарплата, График работы, Аналитика, Настройки.
- [ ] `HeaderDesktop`, `Subnav` и `NavDrawer` используют один и тот же механизм определения активного пункта/раздела (не три независимые реализации).
- [ ] Состав и порядок пунктов верхнего меню задаётся одной декларативной структурой без ручной конкатенации отдельных пунктов.
- [ ] В коде остаётся один тип, описывающий пункт меню, вместо четырёх дублирующих (`HeaderNavItem`, `SubnavTab`, `NavDrawerItem`, `NavLeaf`) — либо оставшееся дублирование явно обосновано в коде.
- [ ] Комментарии про chevron в `navigation.tsx`/`HeaderDesktop.tsx` соответствуют фактическому поведению (нет противоречащих описаний).
- [ ] `npm run lint`, `npm run build`, `tsc` проходят без ошибок.
- [ ] Визуально проверено на десктопе и в мобильной версии: разделы «Продажи», «Аналитика», «Настройки», «График работы» подсвечиваются корректно без регрессий.
